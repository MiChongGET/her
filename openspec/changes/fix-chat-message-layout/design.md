# Design

## Context

当前消息布局代码位于 `src/renderer/src/App.tsx`（JSX 结构）和 `src/renderer/src/styles.css`（样式）。主要问题：
1. 用户消息使用 `flex-direction: row-reverse` 实现右对齐，但这导致元信息（头像、名字、时间）的视觉顺序与 DOM 顺序不一致
2. 用户消息的 `max-width: min(75%, 560px)` 限制过小，在宽屏上造成不必要换行
3. 附件直接跟在文本后面，没有明确的视觉分隔

See proposal.md - Why 了解问题的具体影响。

## Goals / Non-Goals

**Goals:**
- 修复用户消息布局，使元信息对齐方式与 Her 消息一致
- 调整用户消息最大宽度，减少宽屏上的不必要换行
- 改善附件与文本内容的视觉层次

**Non-Goals:**
- 不改变消息的配色方案或整体视觉风格
- 不改变 JSX 结构（保持现有的 DOM 层次）
- 不引入新的 CSS 框架或工具

## Decisions

### 决策 1：保持 JSX 结构不变，仅调整 CSS

**选择：** 通过调整 CSS 的 `flex-direction`、`text-align` 和间距来修复布局问题，不改变 JSX 的 DOM 结构。

**理由：**
- 当前的 JSX 结构（`.message-avatar` 和 `.message-body` 作为平级元素）已经足够支持所需的布局
- 纯 CSS 修复风险更低，不涉及 React 组件逻辑
- 保持 DOM 结构稳定，不影响测试和其他可能依赖结构的代码

**备选方案：** 重构 JSX 结构，为用户消息和 Her 消息使用不同的 DOM 层次。被否决因为增加了不必要的复杂度。

### 决策 2：用户消息最大宽度调整为 min(80%, 600px)

**选择：** 将用户消息的最大宽度从 `min(75%, 560px)` 调整为 `min(80%, 600px)`。

**理由：**
- 80% 在宽屏上提供更合理的阅读宽度，减少不必要的换行
- 600px 的绝对上限确保在超宽屏幕上文本行长度仍然舒适
- 与 Her 消息的 `min(88%, 680px)` 保持合理的视觉层次差异

**备选方案：** 使用与 Her 消息相同的宽度。被否决因为失去了视觉层次的区分。

### 决策 3：附件与文本间距增加到 12px

**选择：** 将 `.message-attachments` 的 `margin-top` 从 `10px` 增加到 `12px`。

**理由：**
- 12px 提供更明显的视觉分隔，符合附件作为独立内容块的语义
- 与消息内其他元素（如 `.message-meta` 的 `margin-bottom: 10px`）保持一致的间距节奏

## Risks / Trade-offs

**[风险] 调整后的宽度在某些屏幕尺寸下可能导致气泡宽度变化明显** → 通过使用百分比和绝对值的 `min()` 函数平滑过渡，确保在各种屏幕宽度下都有合理的表现。

**[权衡] 用户消息宽度增加后，可能在视觉上显得更"重"** → 这是预期的改进，更宽的气泡减少了换行，提升了可读性，这比保持原有的紧凑感更重要。
