# Proposal

## Why

Her 当前只使用有限的当前会话上下文，跨会话的用户偏好、历史证据和可复用经验无法持续利用。本 change 按已确认的 Q1–Q19 建立可查看、可纠正、可遗忘的本地记忆，并在用户空闲时用独立配置的模型整理新增对话。

## What Changes

- 建立三层记忆：短小、稳定的核心记忆；可按需检索原始消息的历史记忆；经用户审核后启用的经验流程卡。单用户全局共享，跨会话、跨模型服务；项目名作为内容和检索线索，首期不引入项目空间。
- 使用 `Intl.Segmenter + SQLite FTS5` 检索核心记忆、历史消息和经验卡。保留原文与来源，索引和查询采用相同预分词；不引入 nodejieba、向量数据库或 Pi。
- 清楚表达的用户事实可自动新增、精确去重；推断和冲突进入待确认。用户直接纠正、明确遗忘立即生效；经验卡新增和实质修改必须审核。
- 稳定的个人偏好、个人事实和长期约定优先常驻有限上下文；项目事实、事件和经验卡按相关性召回。已批准且相关的经验卡可自动参考，并展示本次使用了哪些卡；不增加工具权限。
- 新增空闲整理：Her 内连续 5 分钟无交互且没有前台生成或工具执行时运行；前台优先，应用退出后下次续接。自动整理默认关闭，每日最多 3 个批次。
- 设置中单独选择整理模型，复用已保存服务及凭据，不跟随当前聊天模型。模型缺失、失效或请求失败时保留任务并显示原因，不切换其他模型兜底。
- 支持手动立即发起一个整理批次，不消耗自动日配额；前台忙时等待。手动与自动共用单批输入/输出预算、取消机制和进度展示。
- 默认增量整理启用后的新消息；历史消息可以检索，只有用户选定范围后才回溯整理。统一记忆面板提供核心记忆、来源、纠正/遗忘、经验卡审核/停用、待确认项及整理进度/结果。
- 完整记录来源和派生关系。遗忘移除整条纠正链，并阻断已知来源及其派生内容再次进入模型；来源原文仍可人工查看。回收站暂时排除来源和无其他完整证据支持的派生项，恢复不解除遗忘，永久删除清理失去支持的派生内容。
- 后台成功安静记入面板，待审核显示角标，失败显示状态与原因；不插入聊天通知。手动操作就地展示进度。

首期经验是可检索、可审核的流程卡，不是自动安装或执行的 skills。没有新增通用 Agent 框架、常驻系统守护进程、多用户隔离、自动文件/命令权限或跨设备同步。

## Capabilities

### New Capabilities

- `agent-memory`: 核心记忆、证据来源、纠正与遗忘、来源生命周期联动、受控上下文与用户管理。
- `memory-history`: 中文历史消息检索、来源定位、候选证据边界及检索排除规则。
- `memory-experience`: 经验流程卡的提炼条件、审核、版本、停用、按需使用与来源失效。
- `memory-consolidation`: 独立模型设置、空闲/手动调度、增量与回溯、预算/配额、持久任务、进度与通知。

### Modified Capabilities

无。现有 `settings/system-prompt` 的自定义提示词契约不变；记忆上下文追加在其后。回收站原有对话操作不改变，新增记忆来源联动由本 change 的能力定义；不修改其他进行中的 change。

## Impact

- 存储：沿用 `node:sqlite` 与当前本地数据库，升级 schema，增加记忆、来源/派生关系、审核项、FTS 索引及整理任务/用量账本；迁移失败回滚，旧应用拒绝打开新 schema。
- 核心服务：增加记忆访问与整理服务；复用当前 `ChatService`、工具注册表和模型协议层，扩展工具上下文、来源过滤与请求用量采集。保留现有严格工具校验、取消和聊天事务语义。
- 生命周期：会话完成、重试、回收站、恢复、单个/批量永久删除，以及应用退出/休眠都要联动来源与任务状态；不能仅在 UI 或提示词过滤。
- 桌面接口：扩展共享类型、经过验证的 IPC、preload bridge、设置面板和 MemoryPanel，沿用现有 `her:*` 命名与凭据保护。
- 依赖：使用 Electron 已有的 Intl 和 SQLite FTS5，无新增分词器或 Agent 框架运行时依赖。已有 `benchmarks/` 和 Pi 实验只作为选型证据，不接入正式运行链路。
- 数据边界：记忆及原始聊天本地保存；当前聊天选择的记忆随前台模型请求发送，选定的整理材料随独立后台模型请求发送。关闭自动整理后不再自动发起整理请求，仍可手动整理。
- 验证：每一实现任务包含相应测试；最终覆盖真实 Electron 主进程中的分词/FTS、来源失效、取消恢复、并发纠正/遗忘和进度 UI。本文档更新不代表这些功能已实现。
