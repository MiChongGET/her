# MarkItDown runtime

Install uv separately. For a packaged app, run `sh "/path/to/Her.app/Contents/Resources/dependencies/markitdown/install.sh"` with the actual application path. No checkout is needed: the script locates its adjacent fixed lock. From a source checkout, run `sh resources/dependencies/markitdown/install.sh`. The installer creates the durable `~/.local/share/her/dependencies/markitdown-0.1.8` venv; its uv-managed CPython 3.13.13 base under `~/.local/share/uv/python/` must remain installed. The application discovers and saves this absolute launcher through the MarkItDown preset. It does not use shell PATH or an SDD research environment to launch conversions.

Validated on macOS arm64 only. `requirements-runtime.lock` is the 74-package hash lock, SHA256 `1509b64c2c46e460c6f2ea04218e9b1213ec644698b8cb236a10548c4a5663df`. The corresponding explicit-extra pins are in `requirements-runtime.txt` (SHA256 `19f09cf301797d6f755c402ced65379d7aeada83c41d8a9589e2ef6794d9a037`). Published `markitdown-mcp==0.0.1a7` requires `markitdown[all]==0.1.8`; the lock retains that dependency closure, including Azure/audio/ONNX. Three fixture-only packages (pypdf, python-docx, reportlab) are excluded. Explicit prereleases azure-ai-contentunderstanding 1.2.0b3 and lxml 7.0.0b1 are intentional; pandas is stable 3.0.6. Do not add global prerelease allowance/disallowance or re-resolve unconstrained pins.

Only Host-authorized staged bytes reach the main-only `convert_to_markdown` seam. `MARKITDOWN_ENABLE_PLUGINS=false` is required. The Python process is not an OS sandbox. PDF extraction may be empty or partial, may fall back to plain text for a corrupt file, and supplies no reliable physical page map. XLSX formulas are not recalculated. GUI/package launch and PDF rendering are separate acceptance work.
