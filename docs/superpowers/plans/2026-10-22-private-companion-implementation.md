# Her 私人伙伴 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已确认的私人伙伴交互落实为固定日常入口、可持续且有边界的委托，以及可追溯、可收回的记忆与工作进展。

**Architecture:** 保留 Pi 对会话历史、上下文与压缩的权威，Her 持有话题身份、委托授权与资料使用资格。界面读取主进程提供的状态；动作在现有工具门派发前复核，跨话题内容在进入模型前复核。按 A 空间、B 委托、C 记忆共享三个完整流程交付，分别验证后再整合。

**Tech Stack:** 当前仓库锁定的 Electron 44、React 19、TypeScript strict、Pi SDK 1.3.0、node:sqlite、Vitest、Playwright Electron。

**Spec:** [已确认的交互设计](../specs/2026-10-22-private-companion-interaction-design.md)；[委托授权 ADR](../../adr/0007-authorize-bounded-delegations.md)、[修正优先 ADR](../../adr/0008-prioritize-delegation-corrections.md)、[共享撤回 ADR](../../adr/0009-revocable-work-progress-sharing.md)。

状态：2026-10-22 用户确认实施计划并要求继续实施，按子代理逐任务实现与独立审阅推进。本文是入口，实际任务与接口见三个子计划；任务勾选及验收记录表示实际完成范围，不将规划完成计作功能完成。

## Global Constraints

- 日常主聊天是默认入口。工作另开话题，用户可以自然回到日常主聊天继续相处。
- 委托以事情完成或用户明确取消为结束。应用重启后等待用户要求继续。
- 预订、付款或提交个人资料时另行确认；明确普通消息发送仅满足 Q5 的全部条件时免重复点击。
- 拒绝针对具体步骤，不自动取消整件委托；不得换工具或换种说法重新尝试同一个被拒绝的动作。
- 关闭工作话题的“带回日常”后，该话题已经带回的摘要及派生记忆也不再用于后续日常回答。
- 未共享话题在日常及系统通知中只显示通用待处理提示，不显示标题、对象或正文。
- 纠正、别记、遗忘各自沿用产品定义；停止使用、界面隐藏和创建新分支均不等于清理原文。
- Pi 历史权威、资料失效过滤、未知动作隔离继续有效；不绕过现有参数、配置、资源与派发校验。
- 数据仍位于 `Her-Pi-v1`；SQLite `user_version=1`，不读取或迁移旧版目录，不重置当前用户资料。
- 本计划的新表为当前 v1 的增量工程设计；不套用旧记忆提案的 v7→v8，也不借机扩大为通用 schema 迁移系统。
- 保留当前工作区其他任务的变更。当前分支含大量尚未提交的 Pi/浏览器改动，不从远端默认分支假定出同一基线，不自动提交、推送或归档既有 OpenSpec changes。
- 语音、世界行为、提醒系统、向量检索、经验卡和主动联系算法不在本次改动内；世界面板若尚未实现，不用静态画面伪装真实状态。

## Review Focus

1. 原工作标题通过启动数据、后台事件或通知泄露到日常：A 用 DTO、事件订阅和实际模型请求体回归。
2. 等待资源/审批期间收到停止或修改，旧批准仍派发：B 用屏障、版本和派发计数回归。
3. 任意浏览器脚本、换工具或模型自报动作类型绕开边界：B 用不透明执行与跨工具拒绝回归。
4. 已撤回的共享内容通过旧压缩摘要、迟到整理或重启回来：C 捕获普通、压缩、恢复请求及迟到写入。
5. 遗忘中途崩溃，只清了显示却保留旧正文：C 检查持久内容和每个清理阶段的恢复结果。

A 先落地，B/C 的技术探针可并行只读研究；正式实现按 A→B→C 合并。三个子计划共同修改 `store.ts`、`host.ts`、共享类型与 IPC 时必须串行整合，不安排代理同时修改这些文件。

A 中新工作话题保存默认共享偏好，但 C 完成前不生成或注入共享摘要。既有会话不自动追认成日常，也不自动回溯共享历史；未来由用户在工作界面明确开启共享。

## 跨计划合同

以下是拟新增接口，不能当作当前代码已存在的类型。它们集中在 `src/shared/types.ts`，主进程服务是状态权威。

```ts
interface TopicInfo {
  conversationId: string
  kind: 'daily' | 'work'
  shareProgress: boolean
  shareRevision: number
}
interface PendingActionNotice {
  id: string
  status: 'waiting_approval' | 'paused' | 'unknown'
  version: number
}
```

- A 拥有话题身份及只含不透明定位信息的概览；B 让概览消费委托状态，不在日常批量读取完整 `TaskEvent`。
- A 提供 `resolvePendingAction(input: { id: string; version: number }): Promise<{ conversationId: string } | null>`；过期、已处理或不可访问事项返回 `null`，不从通知载荷恢复旧卡片。
- C 拥有共享切换的版本事务及撤销效果，A 的工作页开关经该服务操作；禁止 UI 直接改 `shareProgress` 绕开来源撤回。
- B 的委托 ID 不等于话题 ID、运行 ID 或调用 ID。一次运行结束不能自动证明整件委托完成。
- C 的来源以 Pi `sessionId/entryId` 和宿主发出的版本引用为依据；投影、模型自报来源、通知文本都不能成为授权或记忆的事实来源。
- 两类状态分开：界面能显示待处理状态，不代表日常模型能读取该事项内容；系统能力已可用，也不代表具体动作已获准。

## 工程门槛

1. **受控动作探针（B）**：先复用已有 HTTP 搜索/读取，在主进程验证委托范围与目标，完成首条连续比较流程。需要浏览器操作时，另证明固定模板确实限定类型与对象，不退回执行任意模型代码。点击可能提交，未知动作继续单次确认；浏览器探针失败阻断该项自动能力，不阻断已通过的 HTTP 比较流程，也不能将前者标为已完成。
2. **Pi 清理探针（C）**：公开 API 不允许原地删除条目。验证通过公开 `SessionManager` 创建清理后的新会话、维持有效关系并切换映射的方案；清理状态持久化且旧文件最后删除。不能完整满足时阻断遗忘交付，不能静默改成隐藏或手工重写 JSONL。
3. **通知权限探针（A）**：`Notification.isSupported()` 不证明用户已授权。只有 Her 自己的真实权限状态为 authorized 才发送系统通知；状态未知时保留 Tray。必须分别记录 Tray 已验证与系统通知分支的验证结果。

这些是工程验收门，不重新询问已定产品规则。探针失败后记录具体能力缺口，修改技术方案并复核；涉及改变产品承诺时再向用户说明取舍。
