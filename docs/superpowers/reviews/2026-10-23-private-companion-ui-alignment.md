## 未完成能力的现实边界

| 能力 | 当前可支撑的页面 | 当前不能宣称 |
| --- | --- | --- |

## 第三轮已确认：页面状态与操作

用户先指出 Q6 的聊天回复表格遗漏“她记得的事”，随后确认：“Q6 补上她记得的事这一行，Q6、Q7、Q8 都同意，继续梳理卡片内多委托状态、历史与管理操作，以及原型未覆盖页面的布局。”下表包含完整四行。

### Q6：空状态

| 页面 | 正常空状态 | 可操作入口 |
| --- | --- | --- |
| 日常 | 保留原型的标题、留白和输入框；短句“我在，想说什么都可以。”；没有示例消息、伪造日期或大幅欢迎插画 | 输入与添加资料；尚未配置模型时可先写文字草稿，提示连接模型服务并提供设置入口，发送暂不可用 |
| 一起在做的事 | “还没有一起在做的事”；旧历史不冒充当前事项，在该页面的独立区域访问 | “开始一件事”进入空白工作话题，不要求先填任务表格，不自动派发动作；仅创建动作成功后才出现真实卡片 |
| 新工作话题 | “这件事，我们从哪里开始？”；不冒充已经在办理 | 说明目标、添加资料、发送后沿用现有委托与授权流程 |
| 她记得的事 | Q3 已定的“记忆功能尚未开放”，不作为“已启用但无记录”的空状态 | 返回日常或切换其他入口；没有虚构的记忆加载、启用或管理操作 |

### Q7：加载与失败

- 公共外壳保持原型布局；首次读取只在目标内容区显示轻量加载。切换目标时不把原话题内容放在新标题下，当前目标未核实前不发送、不批准或继续动作。
- 同页刷新可保留先前内容，标明正在更新；刷新失败说明未更新，不把旧状态当作最新状态授予动作能力。后台已获准任务不因界面读取失败而被取消。
- 首次加载失败显示独立错误状态与“重新加载”，不同时显示空状态。文字草稿按所属话题保留；本轮不因此新增跨重启草稿持久化承诺或跨话题转移附件授权。
- 读取重试只重新取数据，不重发消息、不重做外部操作。发送失败保留用户输入和已经生成的部分内容；再次发送沿用现有失败/未知动作规则。
- 待处理入口过期时轻提示“这件事的状态已更新”，刷新提示，保留当前页面与草稿；解析或目标读取失败可重新读取，不跳转到空白新话题。
- 本地数据初始化失败显示明确启动错误与重新加载；不能将初始化失败解释为没有历史。

### Q8：真实状态、数量与动作

本节记录第三轮当时确认的方案。其空闲任务栏与侧栏计数呈现已被后续 Q14 明确取代；真实状态、失败及操作依据的原则仍然有效。

| 已核实状态 | 呈现与可操作内容 |
| --- | --- |
| 日常当前任务无运行 | 可以显示原型中的“没有正在执行的日常任务”，只表达当前日常，不推断其他工作也空闲 |
| 正在回应或办理 | 轻量状态；可停止当前运行、返回日常或切换页面，切换不代表取消 |
| 等待确认 | 主内容区确认入口；进入所属话题后展示准确对象、边界和动作按钮 |
| 已暂缓、失败或中断 | 按真实原因分别呈现；已有结果保留，只有服务允许时才提供继续，不把失败改写为用户主动暂缓 |
| 外部动作结果未知 | “结果待核实”，进入原话题核对和处理；不提供普通“再试一次”重放 |
| 状态未读到或读取失败 | “状态暂不可用”及重新读取；不显示空闲、已完成或零事项 |

侧栏“一起在做的事”的数字表示工作话题总数（包括尚在讨论的话题，不含旧历史），不叫进行中数量；待处理数量单独表达。真实为零时省略数字，尚未读到或读取失败时显示“—”。日常只接收必要的通用计数，不为显示数字下发工作标题或正文。卡片和委托完成仍需真实状态，不能用一次回复结束推断。

Q6–Q8 均已接受。继续收敛卡片内多委托状态、历史与管理操作的呈现，以及原型未覆盖页面的具体布局；不重问既有授权与记忆产品决定。

## 第四轮原建议：多委托、历史、管理与布局（尚未接受，按最新方向重审）

本轮 Q9–Q12 尚未得到用户同意。用户随后要求“淡化工作交集，更多的是生活陪伴”，以下内容仅保留讨论依据，不作为实施依据；最新方向及待决见后文。

### Q9：事情卡片内多委托状态

建议工作列表的一张事情卡同时显示有证据的不同状态及数量，而不是用一个“进行中”覆盖全部，例如“1 项待确认 · 1 项已暂缓”。没有委托则显示“还在讨论”；授权仍有效不能当作正在执行，已完成或取消也不能遮住遗留的结果未知动作。

进入话题后按委托分别查看目标、范围、进展和操作；待处理优先展开，已结束的委托可折叠回看。暂停、继续、取消绑定具体委托，不提供默认作用于全部委托的大按钮。即使现有委托均已结束，也只表达这些委托的实际结果，不自动宣称整个话题已经完成或转为历史。

当前接口不足以提供列表上的完整分项运行状态。后续工程方案需要最小的只读状态汇总，且只在工作范围提供详情；不能循环选中每个话题获取详情，也不能将这些内容混入日常载荷。

### Q10：历史对话的入口和边界

建议在“一起在做的事”页面下方设置默认收起的“历史对话”，保留旧会话的可访问性；不新增第四个常驻导航，不计入工作话题数量，也不标为已完成事情。

展开后按时间访问，进入后沿用聊天布局并明确标记“历史对话”；可以在原会话继续聊天，不自动转换成工作话题，不自动搬入新工作材料或共享范围。已有工作话题即使所有委托均结束，也不会因此进入旧历史分组。

### Q11：管理操作

建议事情卡片及工作/历史详情的“更多”菜单只提供已有的重命名和移入回收站；日常保持固定标题与入口，不在日常页提供新建日常、改名或移除入口。本轮不新增话题级完成、归档、置顶或批量管理能力。

移入回收站用就近确认说明可恢复；如会停止任务，同时准确说明停止当前话题运行、暂停队列和撤销待审批，已经发生的操作不撤销。该操作不宣称取消全部委托。恢复回到原话题身份，只恢复查看，不自动继续或重放批准。永久删除继续只在回收站提供，保留现有单项/批量确认、清理失败及重试能力。

设置和回收站入口建议收进侧栏底部的“更多”菜单，保留原型的三个主要入口和底部文案。具体菜单位置属于视觉稿细化，不改变管理能力。

### Q12：原型未覆盖页面的布局

| 页面/区域 | 建议布局 |
| --- | --- |
| 一起在做的事 | 沿用原型公共外壳；主区域顶部标题及“开始一件事”，下方单列事情卡，底部历史折叠区；不把长会话列表重新塞进侧栏 |
| 工作与历史详情 | 顶部返回列表、标题及更多菜单；中间聊天流；底部输入框。权限请求与相关交流相邻，必要授权内容可见，过程和技术记录折叠；不让全部历史委托卡长期堆在输入框上方 |
| 她记得的事 | 同一外壳内的页面标题与轻量未开放说明卡；不展示示例条目、设置开关或加载表象 |
| 设置 | 延续独立居中对话框与已有类别，统一深绿视觉；表单内容内部滚动，不改成常驻主导航；关闭后回到原页面及草稿位置 |
| 回收站 | 延续独立居中对话框，列表与现有确认流程同一视觉体系；保持恢复、清理中、失败和重试状态清楚 |
| 附件、资料授权与来源 | 从“文字与附件”或相关消息就近进入，简要信息折叠展开；长期资料授权仍可在设置管理；不自动授予记忆或行动权限 |

窄窗口下保持单列，内容与表单可滚动，输入框及关键操作可达；菜单、折叠与对话框支持键盘及焦点返回。以上为待确认设计，不是已实现或已通过视觉验收的结果。

### Q15：日常交流何时另开话题

普通生活交流持续留在日常，不因谈到旅行、书、心情或一个小打算就自动拆出事情卡。用户从第二入口主动另开，或接受“要不要单独聊聊这件事”的轻量建议后，再进入独立话题；不反复建议整理，也不先建卡再要求用户接受。明确托付执行事务仍按既有话题归属与授权规则办理，不把当前建议解释为禁止实际办事。

这需要细化旧交互设计中“根据用户目标建立或选定话题”的触发边界；日常倾诉和讨论不等于委托，也不因另开话题获得长期记忆或执行许可。当前没有已验收的自然语言主动拆分入口，不能把模型口头建议当作已创建。
