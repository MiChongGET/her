# Her 内置工具运行时设计

日期：2026-10-16。状态：**已被用户后续指令替换，停止实施随包方案。** 用户改为保留依赖分装，缺少工具时提供安装提示、步骤和按钮；见 2026-10-16-her-dependency-install-guidance.md。本方案曾获同意，但在产品代码和运行时产物准备前已被替换，仅作为历史设计保留。

## 意图与成功标准

用户希望把 Peekaboo、Playwright MCP、MarkItDown 的依赖一起打包，让普通用户安装 Her 后尽量直接使用。此前“分装工具运行时”的取舍被本需求替换；现有 MCP 客户端、任务确认、停止、未知动作及文件授权边界继续沿用。

成功标准：在未安装 Homebrew、Node、Python、npm、pip、uv 和旧 Her 工具目录的 Apple Silicon Mac 环境中，复制 Her.app 即具有完整工具执行文件。文件解析和无需浏览器的网页检索不依赖额外安装；Mac 操作经用户授予系统权限后可执行；现有 Chrome 的自动化仍由用户安装官方扩展并批准连接。构建者负责准备依赖，终端命令不进入最终用户使用流程。

本次推荐并由实施者承担的默认选择：继续 macOS arm64，完整运行时随包，保持现有 Chrome 扩展模式，不附送另一套浏览器。现有 Node24.14.0、CPython3.13.13 和工具锁定版本先保持，避免把运行时升级混入此需求。

## 范围

| 能力 | 随包内容 | 首次使用仍需用户完成 |
| --- | --- | --- |
| Mac 操作 | Peekaboo4.9.3 原生二进制与必要发布资源 | macOS 屏幕录制和辅助功能授权 |
| Chrome 操作 | 独立 Node24.14.0、Playwright MCP0.0.83、锁定 JS 依赖 | 现有 Chrome、官方扩展、连接及标签范围批准 |

最终用户不安装构建工具或语言运行时。Chrome 若不存在，设置页明确说明并提供官方安装入口；不偷偷安装浏览器或建立替代 profile。不存在 Chrome 不阻止文本/文档、Mac 工具和 request 模式搜索。

本次不扩大文档格式/OCR/公式重算范围，不加入其他操作系统或 Intel 架构，不升级第三方工具，不替用户授予权限，不变更真实模型服务及凭据，不扩大现有可调用工具清单。

## 当前代码与需要改变的位置

- `scripts/package.mjs` 当前仅把固定清单/说明作为 extraResource，工具本身不在包中。
- `src/core/mcp/dependencies.ts` 从用户家目录查找外置 Peekaboo/文档环境/JS包，从固定系统路径查找 Node，且 MarkItDown 校验依赖当前 venv 绝对路径。
- 主进程目前在 `src/main/index.ts` 创建 PresetDependencies 并通过既有 MCP 管理器执行；保持这一调用链。
- 现有 MarkItDown launcher 的 shebang 指向开发机家目录。Python 官方说明 venv 一般不具可迁移性，因此本设计使用可移动 Python 发行环境，并直接以模块方式启动 MCP，不复制现成 venv。[Python venv 文档](https://docs.python.org/3/library/venv.html)
- 当前 MCP 设置页/预设已有依赖检查，继续使用该界面；不重做设置布局。

## 随包布局与构建

推荐资源布局，具体小型模块/脚本文件名由构建者决定：

```text
Her.app/Contents/Resources/tool-runtimes/
  manifest.json
  THIRD_PARTY_NOTICES/
  darwin-arm64/
    peekaboo/peekaboo
    node/bin/node
    web/node_modules/...
    python/bin/python3
    python/lib/python3.13/site-packages/...
```

运行时位于 app.asar 之外，通过 `process.resourcesPath` 定位。Python 使用 python-build-standalone 的固定 macOS arm64 发行包；解释器、标准库、动态库及74个依赖属于同一可移动环境。Python 以 `-I -B -m markitdown_mcp` 启动，不依赖 activate、PYTHONPATH、用户 site-packages、旧 venv shebang 或 uv 基础解释器路径。必要的 Python 配置由受控启动层设置，不能引入系统 Python。发行包路径与许可证元数据依据上游格式处理。[Python 发行包说明](https://gregoryszorc.com/docs/python-build-standalone/main/distributions.html)

独立 Node 直接启动固定包的 JS CLI，不以 Electron 的 RunAsNode 模式兼作工具运行时。最终用户端不需要 npm；构建机使用 npm ci --ignore-scripts、PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 准备现有固定锁。Python 构建安装使用现有74包哈希锁；不得在用户第一次启动时 pip/npm/uv 下载或重建环境。

构建脚本在干净、应用自管的 staging 中准备运行时，不复制开发者现有 ~/.local、虚拟环境或已配置的 MCP 服务。固定归档的来源、版本、架构和 SHA256 在准备产物前记录并校验；不使用 latest 或宽版本范围。准确归档 URL/构建标签/摘要由实施预检从官方 Node、Peekaboo 发布产物及 Python standalone 固定发行记录确定，并写入版本控制用清单。下载缓存可复用，但每次使用仍校验；校验失败不继续打包。当前普通 `npm run package` 生成完整包，不能悄悄生成缺依赖的“精简成功包”。

产物清单记录组件版本、架构、入口、必需资源和内容完整性；保留许可证及必要 NOTICE。包内容排除用户数据库、凭据、个人路径、开发缓存、测试与研究环境。构建产物需要能在另一条含空格和中文的路径运行。

## 查找、启动与可写数据

安装版只使用当前 Her.app 的受信内置运行时，缺失、损坏或架构不匹配时明确报错；不静默回退到用户 Node/Python、旧 Her 依赖目录或在线安装。源码开发仍保留已有分装依赖方式，便于开发调试，不能用其通过结果冒充安装包独立运行。

运行前按可信构建清单验证二进制、解释器及工具包，保留现有参数、环境和工具允许清单。可编辑 presetId、远端 annotations、同名程序或未知配置不能因此取得可信预设权限。MCP 自定义服务保持原有用户配置和信任边界。

应用包视为只读。Playwright 输出、Peekaboo 缓存、临时文档、Python/第三方库运行缓存写入 Her 自管的可写数据目录；不得写回 Resources、依赖系统目录，或为启动 chmod/修改用户原文件。文档插件继续禁用。运行时自管子进程仍服从现有停止与退出预算。

不把宿主可任意覆盖的用户环境全部传入子进程；沿用原有允许的环境和固定默认值。内置解释器不会引入 shell、npx、pip、下载器或额外模型执行入口。

## 预设初始化、迁移与应用移动

新安装预置 Mac/文档/Chrome 三个内置预设，让用户不必逐个手填命令和路径；可选搜索保留默认关闭。系统权限或 Chrome 尚未就绪时显示相应状态，不把它们称为“依赖需要安装”，也不阻止普通聊天。预置配置不意味着绕过首次权限确认或自动触发浏览器配对。

用户删除/停用过的预设不能在每次启动被重新加回来。首次初始化须有持久完成标记，且不覆盖同名自定义服务。既有受 Her 管理的预设迁移保留服务ID、名称、启停状态和秘密数据；只重新绑定确认属于旧固定预设的运行时位置。无法证明属于旧内置预设的配置保持原样并提供明确修复指引，不能擅自执行旧命令来鉴别身份。

内置预设逻辑身份与安装绝对路径分开保存。应用移至 /Applications、改名、放在含空格/中文的路径或覆盖升级后，启动时从当前 Resources 解析入口，不能继续指向构建目录、旧应用位置或开发者 home。绑定/迁移所用内部数据字段及必要 schema 迁移由构建者以最小实现决定；renderer 任意字段不能成为信任证据，当前版本/CAS 与配置变更失效语义保持。

Mac 权限、Chrome 扩展及连接范围只做现有设置中的明确引导，不自动批准，不把“依赖 ready / 元数据连接”显示为“浏览器已经连接”。如果需要新增跳转按钮，只接受 Host 固定目的地，不开放任意本地协议执行。

## 更新、完整性与发布边界

本次运行时随 Her 版本一起升级，不另建后台更新器，不对已经运行的依赖原位自修改。更新不重放原任务或 unknown 动作，不清理用户另外安装的依赖目录。

打包准备和校验要考虑将来代码签名会改变 Mach-O 内容摘要：原始发布包校验与最终包内产物校验分开；最终清单由可信构建过程在必要签名步骤后生成，运行时不从待验证文件自算期望值。禁止为迁就重签名而取消来源校验。

当前未配置 Developer ID；本次交付本机可测的完整包与依赖清单，保留现有未签名/未公证状态说明。公开分发仍需将嵌套可执行文件/动态库与 Her 一起纳入签名、公证流程；没有证书时不能宣称已达到无 Gatekeeper 提示的公开发布状态，不自动调用开发者账户。[Electron 签名与公证](https://www.electronjs.org/docs/latest/tutorial/code-signing)

## 验证与验收

1. 核心测试：安装版来源选择、缺组件/坏摘要/错误架构、参数与环境绑定、旧预设迁移、应用移动后重解析、首次初始化幂等、删除/停用保留、自定义服务不变、原有 CAS 和运行失效机制。
2. 构建测试：固定锁/归档摘要正确，staging 不取用户工具目录，不遗留开发者路径，必需资源与许可文件齐全；缺工具时 package 失败。
3. 干净环境实际包：独立 HOME/userData、系统 PATH，无旧 Her 依赖目录；不修改真实用户环境来模拟干净机器。验证 bundled Node/Python/Peekaboo 版本、全部文档关键导入、MCP 发现和自管退出。
4. 真实解析：从包内 Python/MCP 解析现有 DOCX/PPTX/XLSX/文字 PDF 合成夹具，输出标记与来源正确；扫描 PDF 继续走既有 PDF.js/视觉路径。
5. 移动/只读：将包复制到含空格中文的另一位置，不能引用原位置或外部解释器；保持 Resources 只读，解析与输出目录写入正确。用未准备用户工具环境的测试运行，保留实际包资源 hashes 与子进程收据。
6. 浏览器：无需 Chrome 时 Node/Playwright MCP 元数据可用，明确缺少浏览器/扩展；实际标签控制仅在用户批准安装和连接后验收，不使用其他浏览器或 profile 代替。
7. Mac：包内 Peekaboo 权限状态与实际读取/输入分开；权限未授予不自动处理，已授权时再做合成窗口验证。先前物理停止和 unknown 语义不因打包改变。
8. 完整回归：现有 check、Electron/包回归均保持；应用自管进程正常退出，真实用户 Her、Chrome、依赖目录、凭据及聊天历史不变。

干净 HOME + 系统 PATH 是本机隔离验收，不能假称已在第二台实体 Mac 验证。压缩/解压体积与准备/首启耗时按产物实测填写；本机外置依赖目录当前 du 合计约585MiB，仅是大小参考，不等于最终包新增量。Node和最终裁剪/签名都会改变结果。
