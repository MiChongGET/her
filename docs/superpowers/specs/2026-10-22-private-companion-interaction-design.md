# Her 私人伙伴交互与授权设计

日期：2026-10-22

状态：Q1–Q13 已确认，独立设计审阅未发现关键待决问题；用户于 2026-10-22 确认设计基线及实施计划，已进入实施。具体完成范围以实施计划勾选和验收证据为准。

实施拆分与验收顺序见[实施计划](../plans/2026-10-22-private-companion-implementation.md)。

## 设计依据

Her 是只为用户本人长期使用的私人 AI 伙伴。本次设计将长期相处、共同工作与明确授权落实到交互中。

沿用[产品与技术设计](2026-10-13-her-design.md)中的伙伴设定、个人偏好共享和项目材料分开的方向；已有温暖视觉语言可以延续。界面中的记忆、待续事项和执行结果必须由实际能力和记录支撑。

本次设计覆盖日常与工作话题的组织、记忆和进展的使用边界、委托授权、执行中的修正，以及权限请求的完整交互。语音和虚拟世界沿用原产品方向，本次只定义它们与主窗口的关系；其具体实现另行安排。

成功标准是用户能持续和同一个伙伴相处，清楚知道她在做什么、已经获准做什么，并能及时修改或收回托付。实际效果通过文末场景验收，不能只以界面文案更亲切或权限弹窗更少判断。

## 已确认的决定

### Q1：固定日常入口与工作话题

日常主聊天是默认入口。工作另开话题，用户可以自然回到日常主聊天继续相处。工作话题与日常主聊天共用伙伴身份，工作材料保持各自范围。

工作信息通过 Q4 的进展摘要带回日常主聊天；待续事项按后文界面默认值呈现，供整体审阅。

### Q2：以事情及其边界组织授权

用户批准的是一件事及其明确边界，Her 可以在该范围内连续执行。范围应能表达目的、对象和结束条件。

已确认的示例：用户委托比较三家酒店时，可连续浏览、筛选和整理；预订、付款或提交个人资料时另行确认。

[工具专项设计](2026-10-15-her-tools-v1.md)要求发送、删除、覆盖前逐目标确认；Q5 对明确指令下的普通消息发送作有限调整，其他动作不能据此扩大授权。委托的结束与续接见 Q6。该方向记录于 [ADR-0007](../../adr/0007-authorize-bounded-delegations.md)。

### Q3：自然解释与准确授权内容并存

Her 可以自然地解释为什么需要这项权限。系统卡片准确展示用户实际批准的内容，例如读取对象、是否发送给当前模型服务、有效范围与撤销方式。解释与授权内容必须一致。

资料访问、Her 的动作授权、macOS 权限和外部服务连接同意各有实际边界，需要在后续流程中表达清楚。

### Q4：工作进展带回日常

允许日常主聊天自动知道简短工作进展，以及用户在工作话题里明确表达的感受，以便自然延续交流。原始文档、代码和详细讨论留在工作话题；每个工作话题都可以关闭“带回日常”。

工作进展摘要本身属于项目信息，需要明确的共享范围与来源依据。关闭共享的影响见 Q11；呈现方式见后文界面默认值。

### Q5：明确的最终消息指令可以构成批准

已确认的场景：用户说“在微信里给张三发：我晚十分钟到”，联系人唯一、最终内容完整且目标已经核对时，指令本身构成这次发送的批准，不再重复要求点击允许。

如果用户只说“帮我回复一下他”，由 Her 拟定的内容应先展示，取得批准后再发送。预订、付款和提交个人资料继续单独确认。删除、覆盖等场景未因本次决定而改变原有确认规则。

该决定调整的是批准的交互形式，执行前仍需校验实际目标、内容与用户指令一致。

### Q6：委托可以跨天续接

委托以事情完成或用户明确取消为结束。切换话题不取消委托；暂缓后保留进展与原有边界，用户次日可以继续，无需重新交代全部信息。应用重启后等待用户要求继续。

恢复时重新核对目标和范围，关键内容变化再询问；结果未知的动作先查清，不能直接重做。委托的持续有效不表示旧工具调用批准可以跨运行重用。

### Q7：记忆可查看、追溯与纠正

提供轻量的“她记得的事”入口，展示记忆内容、来源与使用范围，允许用户直接纠正或要求忘记。在已允许记忆的范围内，普通整理不逐条弹窗打断。

用户可以直接说“这个已经变了”“这件事别再记”。Her 引用过去的事情时，可展开查看依据。纠正、别记和遗忘仍沿用原产品设计各自的含义。

### Q8：工作话题中的明确修正优先处理

用户在当前工作话题里说“先别发了”时，立即阻止后续发送；说“把预算改成五百”等修改要求时，先暂停相关后续动作，核对新范围后继续，有歧义才追问。已发生的动作按真实结果告知。

该决定调整原先将所有新消息排到任务之后的规则。普通补充、无关聊天和控制指令必须区分；多件委托同时进行、用户在日常主聊天中没有唯一指代时按 Q10 处理。方向记录于 [ADR-0008](../../adr/0008-prioritize-delegation-corrections.md)。

### Q9：拒绝某一步后继续其余获准工作

拒绝针对具体步骤，不自动取消整件委托。例如比较酒店时拒绝提交个人资料，仍可继续比较原授权范围内的其他方案。

不得换工具或换种说法重新尝试同一个被拒绝的动作。确实缺少这一步就无法继续时，说明原因并等待用户调整安排。“暂缓这件事”和“取消这件事”分别提供明确入口。

### Q10：模糊停止指令先拦住候选动作

用户在日常主聊天中说“先别发”，若没有唯一指代，先暂停可能涉及的发送，再问清对象。例如两件委托正在分别准备消息，两项候选发送均先暂停；比较酒店等明确无关的工作继续。

指代清楚时直接处理，不多问一句。该决定保护询问期间尚未发生的动作，不将模糊指令解释为全局停止。

### Q11：关闭共享同时收回既有摘要的后续使用

关闭工作话题的“带回日常”后，该话题已经带回的摘要及派生记忆也不再用于后续日常回答。已经显示的聊天记录仍可查看；清除记录使用独立的遗忘操作，原工作话题仍可使用自己的资料。

该规则记于 [ADR-0009](../../adr/0009-revocable-work-progress-sharing.md)。

### Q12：取消工具全局永久放行

取消“所有对话允许此工具的所有操作”入口。工具连接可以长期保存，行动授权统一遵循每件委托的边界：范围内连续执行，越界再询问。预订、付款等既定确认不能被工具开关绕过。

一致性要求：旧全局放行配置与现有会话级浏览器放行均不能作为绕过委托边界的路径。连接启用、系统能力许可与具体行动授权分别表达。

### Q13：未共享话题仅显示通用待处理状态

关闭“带回日常”的工作话题等待用户处理时，允许日常界面显示“有一件事需要你确认”及查看入口，不显示话题标题、操作对象或正文。点击后进入原工作话题，才展示详情并处理。

窗口隐藏时的通知同样遵守这一限制。该提示只表达待处理状态，不恢复进展共享，也不使日常对话获得该话题的内容。

## 界面设计默认值

以下默认值依据 Q1–Q13 和原设计给出，已随完整方案确认；不表示当前已实现这些能力。

| 区域 | 默认呈现 |
| --- | --- |
| 主区域 | 恢复连续的日常聊天，保留当前交流位置；用名字、简洁头像和真实活动状态表达伙伴在场 |
| 侧边入口 | 日常聊天、一起在做的事、她记得的事；工作话题从事项进入，保持可返回日常的固定入口 |
| 办事状态 | 轻量汇总正在办理和等待用户处理的事项；详细过程在对应工作话题中展开 |
| 技术详情 | 模型配置、用量与原始工具记录收在设置或详情中，日常交流默认显示用户关心的进展与结果 |
| 世界面板 | 首次默认收起，之后保留用户上次展开状态；展开或收起均不阻断聊天与办事 |

### 权限卡片与跨话题提示

当前工作话题中的权限请求与相关对话相邻显示，包含目的、实际对象、将产生的变化、授权边界和对应操作。批准按钮按实际动作命名，例如“允许读取这些资料”或“确认发送”；拒绝步骤与暂缓、取消整件委托分别表达。

跨话题等待事项汇总到轻量的待处理入口，不以全局模态窗口阻塞日常交流。点击后进入所属工作话题查看完整内容和处理。显示多少跨话题信息由 Q13 约束。

窗口隐藏时，默认将待处理状态保留在菜单栏；只有系统通知已获准时才发出不含敏感正文的简短提醒。同一等待事项不反复催促；未响应不构成批准，其他不冲突的获准工作继续。

### 首次使用系统或浏览器能力

沿用[依赖引导设计](2026-10-16-her-dependency-install-guidance.md)的按需检查与用户自行授权规则：当前委托真正需要该能力时解释目的，显示尚缺的 macOS 权限或浏览器连接同意，提供对应引导。

委托已获准与系统能力已就绪分别显示。打开设置、复制命令或 MCP 连接就绪不等于系统权限已授予，检查真实状态后才更新。去系统设置或 Chrome 操作期间保留委托与进展；返回后检查能力与目标，当前委托仍有效时继续。若必须重启应用，则按 Q6 等待用户要求继续。

用户没有授予能力时按 Q9 处理：跳过依赖它的步骤，其余获准工作继续；无法继续时说明原因并等待安排。

## 关键交互场景

### 从日常托付一件事

用户在日常提出明确办事请求时，根据用户目标建立或选定所属工作话题，并展示这件事的目标与边界。话题命名、建立和返回入口属于产品组织，不要求用户先填写任务表格。已有范围内的授权不重复索取；缺少必要资料或关键决定时，只询问缺项。

用户可以留在日常交流，工作在所属话题中推进。工作资料不直接进入日常上下文；已允许的工作进展摘要可用于延续交流。若工作没有获准共享，日常只保留 Q13 允许的通用待处理提示。

### 在工作话题处理权限请求

Her 说明这一步为什么有用，系统卡片展示真实对象、实际内容和本次影响。明确消息指令按 Q5 处理；其他需要确认的动作等待用户决定。批准绑定展示内容，目标或关键内容变化后不能沿用旧批准。

选择不做该步后，继续其余获准工作。选择暂缓后保留进展；取消则结束这件委托及其授权。结果未知时先核实状态，不能展示普通“重试”诱导重复执行。

### 回看、纠正与收回

记忆入口展示内容、来源、使用范围和当前有效状态。用户纠正后，后续回答使用新状态；要求别记或遗忘时沿用原产品定义。关闭进展共享后，历史可查看与后续模型能否使用分别判断，不能通过重新摘要把已收回的信息带回来。

## 验收场景

以下是实现阶段需要验证的行为，本轮文档与草图不代表这些能力已经通过验收。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 次日打开应用 | 默认回到连续的日常聊天；真实待续事项可找回，不能编造共同经历 |
| 工作资料与日常相处 | 仅获准的简短进展进入日常；原始材料留在工作范围，摘要可追溯来源 |
| 关闭进展共享 | 后续日常请求、摘要及恢复不再使用该话题的共享内容或衍生记忆；既有记录仍可查看 |
| 私密话题等待确认 | 日常及系统通知只显示通用提示；进入原话题后才见目标与内容 |
| 酒店比较遇到资料提交 | 浏览比较可连续进行，个人资料提交等待单独批准；拒绝后可继续不依赖该步骤的比较 |
| 明确消息指令与代拟回复 | 对象唯一、内容完整、目标核实的消息直接执行；Her 代拟的回复须先预览取得批准 |
| 工作中要求停止或修改 | 控制指令优先处理，后续相关动作被阻止或按新要求核对；已发生结果如实呈现 |
| 多件发送存在歧义 | 候选发送先暂停并询问对象，明确无关任务继续 |
| 重启后恢复委托 | 保留目标、边界和进展，等待用户要求继续；重新校验，不复用旧调用批准或重放未知动作 |
| 旧放行配置存在 | 工具全局和会话级放行均不能绕过委托范围及另行确认规则 |
| 首次系统权限未就绪 | 明确区分业务批准与系统同意，实际检查后更新；其他能力和日常交流可继续 |

## 留给实施方案的选择

委托与运行的存储映射、Pi 会话组织、控制指令识别与派发机制、共享摘要的来源追踪、具体控件与布局适配，由实施方案给出并验证。这些工程选择必须满足已确认的行为，不得扩大授权或缩减撤回效果。

记忆、进展共享、跨天委托和即时修正都需要运行能力支持，无法仅通过修改界面达成。后续实施计划应按可验证的完整使用流程拆分，并明确真实模型、系统权限和打包应用的验收范围。

## 与当前实现的关系

当前界面和审批按会话与工具调用组织，本次方向尚未落入实现。会话记录、模型上下文、委托和任务运行仍是不同概念；日常主聊天的长期连续性不等于一个无限增长的模型上下文。

本次讨论尚未决定修改既有 Pi 历史权威、来源过滤和未知动作规则；它们分别以现有 ADR 和 Pi 适配设计为依据。
