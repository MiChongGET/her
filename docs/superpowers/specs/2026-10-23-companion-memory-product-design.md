# Her 私人 AI 伙伴的记忆产品设计

状态：2026-10-23，产品设计最终汇总版，Q1–Q26 已逐项确认；独立缺口审阅提出的三个问题均已获得用户决定并合入。无剩余待决产品问题；本版供用户整体回读确认。**仅设计，不写代码，不以本文件授予实施许可。**

逐项问题、情景和用户决定保存在 [访谈记录](2026-10-23-companion-memory-product-interview.md)。本文件是后续产品验收和工程规划的完整基线，规定产品效果与边界，不指定技术实现，也不声称功能已经实现。§10 记录审阅闭合，§12 提供全部决定的追溯索引。

## 1. 产品意图

让 Samantha 能有依据地延续与用户的相处：记得重要偏好、持续关切、经历和共同约定，理解变化，适时接起过去的话题；用户始终知道她记住了什么、为什么记、在哪里使用，以及怎样改变或收回。

记忆帮助当下交流，不用于建立无所不知的人格档案。她不靠反复罗列过去来展示熟悉，不把推测固化为标签，不因离线或清理记忆对用户施加内疚或关系惩罚。后一句沿用原产品 §7.3 的相处基线，不新增好感积分系统。

### 本次范围

个人与工作范围的记忆、真实共同经历、有来源的关系理解、工作进展共享，以及记住、纠正、不主动提、别记、遗忘、启停和来源查看。

本次不增加真正不保存聊天原文的临时聊天；它仍是独立的后续能力，不以“别记”或关闭记忆伪装实现。不扩展主动联系、通知算法、虚拟私人生活、外部提醒或业务渠道，不因“她记得”而取得外部行动授权。不在产品设计中指定数据库、索引、模型供应商或检索算法。

## 2. 她记住的是什么

| 对象 | 产品含义 | 不能混同 |
| --- | --- | --- |
| 当前交流材料 | 当前交流起点之后、为理解本段交流而获准使用的内容及暂时理解 | 不自动成为长期个人事实，旧回答和压缩摘要不能绕过起点与许可 |
| 个人记忆 | 在允许范围内、关于用户的稳定偏好、背景、重要经历、持续关切 | 不等于全部聊天或工作资料 |
| 共同经历 | 与 Samantha 实际发生的交流、共同选择和有依据的参与 | 听用户讲述不等于共同在场 |
| 关系理解 | 有来源的相处方式、共同约定、表达边界和真实共同经历 | 不能是隐藏的人格诊断或免于遗忘的另一本档案 |
| 工作记忆 | 围绕原工作事项的材料、认识和进展 | 不自动成为跨话题个人记忆 |
| 工作进展摘要 | 允许带回日常的简短进展及明确的一般工作感受 | 不是完整材料、代码、详细讨论或敏感倾诉 |
| 任务和动作结果 | 实际办理的进展、承诺、尝试及有证据的结果 | 计划、运行结束、口头说办好不等于事情完成 |

自动取舍以未来能否帮助理解用户或延续交流为依据。有意义的生活小事也可记，不限于办事；普通每餐、点击和流水账不自动长期沉淀。已发生但只是用户讲述的事，按“你告诉过我”保存参与视角。

来源必须能支持这项认识。明确用户陈述、实际交互和经核实的业务结果各有不同证据边界；附件里的第一人称、引用、故事或模型自己说过的话，不自动证明是用户的事实。用户可指定过去的聊天或材料补记，但只能在所选内容与允许范围内进行。

## 3. 许可分别建立，同时生效

第一次以简短说明让用户明确开启个人记忆，说明使用范围和实际模型处理路径。之后在允许范围内普通整理不逐条弹窗；明确记忆指令及时处理，避免把自然交流变成审批流程。

| 许可或控制 | 允许什么 | 不自动允许什么 |
| --- | --- | --- |
| 资料读取 | 当前获准的阅读 | 长期个人记忆、跨话题共享 |
| 个人记忆启用 | 在允许范围内整理和使用个人记忆 | 所有敏感内容、全部旧历史、任意接收服务 |
| 工作进展共享 | 日常使用该工作的简短合法摘要 | 原始材料、详细讨论、敏感倾诉、行动授权 |
| 敏感分享许可 | 具体敏感内容在明确范围内进入日常交流 | 长期个人记忆许可 |
| 独立个人记忆许可 | 将工作中明确要求“以后各处记住”的具体个人内容跨话题使用 | 其他工作内容或自动摘要改名后免于撤回 |
| 记忆传输许可 | 必要且获准的记忆与其衍生片段交给指定模型服务处理，详见 §8 | 整库上传、额外第三方记忆服务、解除内容限制、自动发送普通旧聊天 |

工作话题里“这次不要红眼航班”只用于当前安排；“我一向不喜欢红眼航班，这个偏好以后各处都记住”才形成单独的个人许可。该条保留来源并清楚展示独立范围，不随工作共享关闭一起撤回，但可单独停用或遗忘，且仍受个人记忆总开关和服务许可控制。

关闭工作共享收回普通工作摘要及其派生认识在后续日常的使用；不能靠给摘要改名为个人记忆绕过。独立个人许可仅独立于这个共享开关，不是来源清理、遗忘或其他限制的通行证。原工作话题仍可使用自身合法资料，既有聊天仍可供用户查看；未共享工作的日常与通知仅保留不含标题、对象、正文的通用待处理状态。

## 4. 接纳、变化和过期

### 一般内容

明确偏好变化直接更新当前认识，不要求“纠正”关键词；旧状态保留有效时间和来源。单次例外只作事件，不覆盖稳定偏好。相互矛盾又无法判断为变化或例外时，不擅自覆盖；仅在当下确实需要时简短求证。

同名不能独自证明同一个人。同事小王、大学同学小王依据不足时保留区分或未确定关联，不混用生日、关系或经历；不为完善记忆频繁盘问，也不扩成第三人完整档案。

### 敏感内容

健康状况、亲密关系、财务困境等，默认不因聊到就形成长期个人记忆；明确交代要记住时才纳入相应范围，不重复审批同一明确指令。口令、验证码和完整支付凭据不作为伙伴记忆。

普通工作共享不能自动带回这些敏感倾诉；一般工作感受可按允许范围简短分享，无法可靠区分、或改写仍会泄露敏感事项时留在原工作。允许敏感分享不等于允许长期记住。

曾获准记住的敏感状态明确变化后，旧状态停止作为当前事实，只保留必要失效状态；不自动新增新敏感情况。比如听到“我们分开了”，不继续认定仍在一起，也不因此长期记下分手经过；新状态待用户明确要求后再存。原来已获准的历史仍按纠正、别记和遗忘规则处理。

**停用期间的最小例外（Q26）：** 当次明确得知变化且能确定关联时，仍允许只将原敏感条目标为不再适用，防止重开恢复错误现状。不保存新状态、原因、经过或原话，不开展其他关闭期间的常规记忆整理，不检索旧敏感内容参与回答，也不在重开时回扫关闭期间聊天。关联不确定时不擅自合并或标错，必要时仅核对相关旧认识，不借核对补记。启停说明须解释这项例外，不能把它表达为仍在继续学习用户。

### 时间与真实结果

临时安排到期后不再当作未来计划，缺少结果就保持未知；日期过去不等于已完成、成功或失败。旧短期关切可减少主动提及，仍可回顾；稳定偏好、重要经历不因很久没聊就自动删除。减少提及不取消未完成委托。

她答应过、尝试过、实际完成过各自分开，不把自己的成功宣称当作真实业务结果。

## 5. 回忆怎样改善相处

正在交流时，可以自然想起确实相关且有帮助的过去，不必等用户问“你记得吗”。不每次开场列近况、不为了展示记忆插话，也不例行追问所有未完事项。

只有大意时不编日期、人物、原话或结果；没有找到依据不等于用户从未说过。确实影响当下才简短核对，不机械逐句报出处，但用户可展开依据。

敏感记忆仅在与当前话题或明确需求直接相关时适度使用；允许记住不等于随时主动提起。用户当次不想聊就停止追问，不将其自动解释为删除。

“不主动提及”是一项持续限制：保留内容，不主动引入；用户主动谈及或明确问起时仅允许当次使用，一次询问不自动解除今后的限制。仅聊到相邻领域不构成放行；没有当次触发，也不能暗中用受限内容改变推荐、态度或关系理解。后句是 Q13 使用限制的明确解释，并非新增许可。关系摘要和其他派生认识不能被用来规避这项边界。

## 6. 用户控制与生命周期

| 操作 | 实际效果 | 保留或不改变什么 |
| --- | --- | --- |
| 记住 | 在允许范围与必要开关满足时保存指定认识 | 不扩大到其他内容或外部行动 |
| 纠正 | 更新当前认识，旧状态停止作为现状，保留过去的时间边界 | 不改写“当时实际说过什么” |
| 不主动提 | 保留内容但不主动引入，仅按用户当次主动请求使用 | 不自动删除或解除今后的限制 |
| 别记 | 对所选片段排除长期记忆和关系整理，已有相关派生不继续借道使用 | 聊天原文可保留，不承诺无记录 |
| 遗忘 | 按明确选择清理原文、记忆、摘要、关系派生与索引等范围内内容 | 独立产物按预览明示保留，不默认取消外部委托或删除原文件 |
| 关闭个人记忆 | 停止新增长期记忆与后续使用已存个人记忆，建立新交流起点；仅保留 §4 的最小敏感失效处理 | 已有内容可查或另行遗忘，工作共享开关不被暗中改变 |
| 重新开启 | 恢复仍有效、仍获准的旧内容并处理之后的新内容 | 不补记关闭期间，不复活撤回、排除或遗忘的来源 |
| 关闭工作共享 | 收回普通摘要及其派生认识的后续日常使用 | 原工作合法使用、可见聊天，以及明确独立个人许可分别处理 |

首次开启默认从当时开始，不自动翻阅全部旧聊天或扫描资料。补记时由用户选定历史和内容，不一次扩大到所有过去。

### 停用后的交流连续性（Q24）

关闭时建立明确的新交流起点。旧聊天仍可供用户查看，但其原消息、旧回答和压缩摘要不再自动进入后续回答，避免此前带入的记忆继续影响交流。

起点之后，用户重新提供的内容可用于本段连续交流，段内压缩遵守同一边界；跨天或重启恢复时，不自动带回关闭期间的个人事实，也不借重新开启补记或恢复使用这些事实。用户主动选定旧片段继续聊，可以当次理解，不等于允许长期保存或恢复其他旧记忆。未完成工作按自身独立范围继续，不将全部工作状态一并丢弃。

用户可理解的取舍是：停用后再次回来继续旧话题，可能需要补充背景。具体连续段识别留给工程方案，不能削弱明确的关闭、跨天和重启边界。当前起点可用的新输入也不自动拥有 §8 的跨服务传输许可。

### 停用时的指令与遗忘

记忆关闭时又说“记住这个”，明确说明当前关闭、本次尚未长期保存；给出开启后保存指定内容的选择。不能为了保存一句话静默打开总开关或恢复其他旧记忆。明确开启后按正常恢复规则处理，补记只针对指定内容。

遗忘范围不清楚时先给候选和影响范围，明确的同一单项指令不反复要求确认。预览包括有关联但将保留的独立笔记、成果等；不能把忘记聊天变成取消事务。处理中、失败或部分未完成均不得称“已遗忘”。这里只承诺 Her 可访问范围内的逻辑清理，不承诺撤回已交给服务方或用户导出的内容，也不承诺磁盘取证级擦除。

## 7. 记忆概览与反馈

“她记得的事”优先展示当前有效的认识和共同约定，区分个人、实际共同经历与工作共享。可展开来源、形成与变化时间、使用范围和主动提及限制。过去、停用和被替代的认识仍可查和控制；真正遗忘的正文不能因“历史可查”继续保留。

查看来源是给用户看的，不重新许可模型使用。默认日常和通知不因概览刷新而批量带入未共享工作详情；用户查看原工作内容仍进入其原范围。

明确请求记住、纠正或遗忘，按实际结果简短反馈。收到、排队、处理中与完成区分；失败如实说明状态与必要原因，不口头答应却未生效。普通整理不逐条打断，可在概览或轻量状态查看，不把整理失败转成已完成聊天的失败。

## 8. 模型服务的数据边界

首次开启说明实际保存位置和处理路径。本地保存不等于从不发送：整理或回答时只提供当前必要且获准的材料，不默认上传整库，不暗中增加第三方记忆服务。

首次向新的接收模型服务使用记忆须明确确认，之后不逐条询问；同一服务切换模型不因此重复确认。服务许可不覆盖内容本身的范围、敏感限制、记忆停用或共享撤回，不能承诺服务方撤回已收到内容。

### 覆盖对象和旧历史（Q25）

个人记忆、关系理解、工作共享摘要，以及进入旧回答或压缩材料的记忆衍生，统一受接收服务许可控制；不能靠更名或改作历史绕过。普通旧聊天也不随切换自动发送。要继续旧话题时，清楚说明所选历史的传输范围，同时保持其中受限内容的原有边界；选择历史不覆盖其他许可。

### 拒绝后的交流（Q25）

拒绝记忆许可后，可以使用用户明确要交给新服务的当前输入或选定普通材料开始一段新交流，并说明缺少旧背景。不夹带受限记忆，不自动退回旧服务。无法可靠划清材料边界时，相关材料先不发送并说明原因；代价是继承旧交流需要明确范围，不以整段自动恢复换取无感切换。

首次启用可在同一清楚流程中解释相关范围，无需为同一接收目标重复询问。实际服务身份及配置变更的判定留给工程方案；后续方案必须证明仍是已获准的接收方，不能以模型自报身份或无法确认的旧许可继续发送。

| 关闭后的连续交流与恢复 | 起点后新输入可支撑本段交流及段内压缩；跨天、重启或重开不自动带回关闭期间个人事实，独立工作范围仍有效 | Q24 |
| 主动选定旧片段继续聊 | 按当次允许范围理解，不恢复其他旧记忆，不自动形成长期保存；跨服务仍受传输边界约束 | Q24/Q25 |
| 新服务接收旧历史 | 记忆衍生不能借历史绕过许可，普通旧聊天也不自动发送，继续旧话题须说明选择范围 | Q25 |
| 拒绝新服务的记忆许可 | 可从明确交给它的新输入或普通材料开始，不夹带受限内容、不自动回退旧服务；无法划清的相关材料先不发送 | Q25 |
| 停用期间听到敏感现状变化 | 确定关联后仅使旧条目失效，不保存新情况或经过、不用旧内容参与回答、不回扫关闭期；关联不明不擅改 | Q26 |
