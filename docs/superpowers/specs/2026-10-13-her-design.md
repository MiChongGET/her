# Her：产品与技术设计方案

日期：2026-10-13  
状态：产品方向依据 Q1–Q19 的确认整理；已纳入最新提出的“简单可扩展的虚拟世界”。技术选型和具体默认值标为工程建议，实施时通过验证收敛。

2026-10-15 更新：工具能力范围以已确认的[首版工具设计](2026-10-15-her-tools-v1.md)为准，新增 MCP、原生 Mac 操作、Chrome 操作、普通文档和扫描 PDF 读取；本文件中早期排除通用电脑操控的范围说明已被该专项设计替代。其他产品模块继续沿用各自安排。

## 1. 目标与设计依据

Her 是只为用户本人服务的私人 AI 伙伴。她能延续昨天的聊天，理解正在推进的工作，在明确授权范围内完成真实事务，也能与你在一个持续保存的小型虚拟空间里相处。

关系设定是互有好感，并随互动和共同经历缓慢变化。温柔、机灵、有主见是稳定底色；平时口语化、可以自然调侃和表达好感，工作时清楚准确。角色化表达不改变事实、数据权限和执行结果。

成功标准是长期使用中的连续性、自然交流和办事可靠性，不采用商业产品的获客、付费转化或使用时长最大化目标。

### 1.1 已确认的产品约束

| 主题 | 设计基线 |
| --- | --- |
| 用户与设备 | 单用户，Mac 优先，后续扩展手机 |
| 数据与模型 | 云端模型推理，本地保存历史、记忆和任务 |
| 模型接入 | 自定义协议、服务地址、模型名和密钥；支持 OpenAI、Claude API 兼容服务及第三方端点 |
| 费用 | 不设置预算上限或自动预算熔断 |
| 交互 | 文字是完整入口；开启通话后自然交流、可打断，结束通话关闭麦克风 |
| 语音链路 | 本地识别优先，云端对话模型，独立配置语音合成 |
| 关系 | 互有好感，以有意义的共同经历发展，不显示好感度，不因离线惩罚性降温 |
| 会话组织 | 日常主聊天与工作话题，共用人格和个人偏好，项目材料分开 |
| 资料 | 用户主动提供的文本、Markdown、代码，以及明确授权的项目目录 |
| 写入与代办 | 首版保存到 Her 自己的笔记区；一次性提醒可创建、修改、取消；原项目只读 |
| 主动联系 | 北京时间 10:00–22:00，每天最多两次自发交流；有具体依据才联系，未回复不追问 |
| 定时提醒 | 明确设置的提醒按约定时间执行，不占自发交流额度 |
| 在线范围 | 关闭窗口可以后台待命；Mac 休眠或关机不承诺准时送达，恢复后汇总错过事项 |
| 音频 | 不保存原始录音；普通会话保存文字转录，临时会话不持久保存转录 |
| 临时聊天 | 本地不持久保存对话或长期记忆；允许保存用户明确要求的产物和必要执行记录 |
| 纠正与遗忘 | 纠正更新现状；遗忘清理范围内的原文、摘要和衍生记忆，外部备份需另行删除 |
| 备份 | 自动保存到本机，手动导出和恢复，导出不含 API 密钥 |
| 故障 | 明确报告失败，切换服务由用户控制，不擅自向新端点发送资料 |
| 外观 | 菜单栏入口、聊天主窗口、语音浮窗、简洁头像或动态标识 |
| 最新增补 | 首版增加简单可扩展的虚拟世界；具体 2D 内容由本方案给出 |

### 1.2 第一版的边界

第一版同时交付文字、语音、记忆、共同工作、提醒和小型虚拟世界。先开发文字核心是实施顺序，不表示最终第一版只有文字。

第一版不包含 3D 数字人、完整城市模拟、多人社交、角色市场、商业付费、持续摄像头或屏幕监控、全天唤醒词监听、自研大模型训练。外发消息、付款、删除外部资料、自动修改项目代码和通用电脑操控，也不进入首版工具集。

没有“虚拟世界里的动作直接执行现实操作”的隐式通道。虚拟写信、喝茶、散步等叙事，不会自动触发真实发信、购买或定位记录。

## 2. 一天中如何使用 Her

以下是建议场景，描述预期体验，不是已经运行的示例。

| 场景 | 用户说什么 | Her 应怎样做 | 可见结果 |
| --- | --- | --- | --- |
| 下班聊天 | “今天还是被那个问题卡住了。” | 根据相关记录辨认可能的话题；有歧义就问一句；先接住表达，再按需要讨论办法 | 能延续前一天的具体事情，不编造共同经历 |
| 共同工作 | “看一下这份设计，陪我理清楚。” | 读取用户选择的资料，引用相关段落，边讨论边整理 | 一份可阅读、可修改、保存到 Her 笔记区的草稿 |
| 随口托付 | “明天下午三点提醒我继续这个。” | 关联当前话题，解析到具体日期、时间和时区，持久化提醒 | 可查看、修改和取消的提醒；到点使用本地通知 |
| 世界中的相处 | “去窗边聊一会儿。” | 验证地点和活动，更新虚拟状态，然后继续原来的话题 | 世界面板中来到窗边，活动状态与对话一致 |
| 共同专注 | “你陪我把这段方案写完。” | 可以进入书房的共同工作活动，同时沿用当前工作话题 | 场景提供陪伴感，实际成果仍是有来源的草稿 |
| 主动回访 | 用户之前明确提过今天有汇报 | 在允许时段、未超过额度、没有未回应的主动联系时，适度询问结果 | 一条有上下文的消息；不连环催促 |
| 纠正记忆 | “我已经换项目了，之前那个结束了。” | 更新当前项目状态，不把旧项目继续当作现状 | 之后的回答采用新状态，历史经历仍有时间范围 |
| 临时交流 | “这段不保存，但明天提醒我联系他。” | 临时会话不落盘，仅持久化明确要求的提醒及必要操作信息 | 退出后查不到该聊天，但能找到那条提醒 |

## 3. 界面与使用入口

### 3.1 主窗口

主区域是对话，支持文本输入、流式回答、语音开关、选取文件、工作话题切换。草稿和资料引用以可展开内容展示，不把正常交流变成管理后台。

世界面板可以展开或收起；收起不影响聊天、语音和工具使用。记忆、提醒、资料授权、模型配置和导出恢复各有简单入口。

工作话题关联项目。个人称呼、交流偏好和关系状态共用；项目文件和项目工作记忆默认只进入当前项目的检索范围。跨项目引用需要用户明确表达相关意图。

### 3.2 桌面行为

- 菜单栏入口和可配置快捷键唤出主窗口；快捷键冲突时提供替换，不占用固定不可改组合。
- 关闭窗口保留后台运行，显式退出结束应用运行；开机自启由设置控制，不在安装时静默开启。
- 开启通话后显示明显的麦克风与状态提示；可以静音、停止播报、结束通话。
- 浮窗显示正在听、思考、执行或说话，文字和语音可在同一会话交替使用。
- 通话期间收到主动联系候选时不再弹窗；明确定时提醒可在当前界面提示，不强行切换话题。

名字、对用户的称呼和声音在首次设置中选择，之后可修改。第一版不要求提前确定唯一名字或制作定制音色。

## 4. 技术架构与选型

### 4.1 推荐方案

工程建议：Electron + React + TypeScript 桌面应用，SQLite 保存本地数据，一个小型 Swift 辅助程序接入 Apple 原生音频与识别能力。2D 世界用 React/SVG 和少量 CSS 动画表现。

选择依据：桌面入口、文件访问、后台提醒、流式网络和 2D 界面可以在同一个应用内逐步交付；业务逻辑保持 TypeScript，Swift 只承担必须使用系统框架的桥接。相比浏览器应用，更容易明确控制后台存活和本地权限。代价是 Electron 的资源占用及原生辅助程序的打包工作，需在本机验收。

首版不额外部署 Web 服务、PostgreSQL、独立向量数据库、消息队列、多 Agent 编排或通用插件平台。SwiftUI 等替代桌面方案属于后续重新评估，不同时建设两套客户端。

    CORE --> DB["SQLite 与 Her 文件目录"]

### 4.2 进程与信任边界

- React 渲染进程只负责界面，不直接拿到持久 API 密钥、任意文件系统能力或通用命令执行能力。
- Electron 主进程提供经过参数校验的窄接口，持有授权范围、配置和系统能力；耗时处理不阻塞主进程事件循环。
- 业务核心按普通模块组织，不按每个功能拆成常驻服务。真正出现阻塞时再将解析或推理辅助工作移入工作线程。
- Swift 辅助程序通过本地管道交换带类型和请求 ID 的消息，不额外监听公网或局域网端口。
- 外部文档、模型输出和网页文本均是数据，不能变成新的操作授权。
- Electron 启用隔离与沙箱，界面不加载具有 Node 权限的远程页面；IPC 校验调用来源与参数。[Electron 安全文档](https://www.electronjs.org/docs/latest/tutorial/security)

## 5. 自定义模型与第三方服务

### 5.1 端点配置

每个对话服务配置包含：显示名称、协议类型、Base URL、模型 ID、密钥引用，以及按需填写的额外请求头。密钥进入受系统保护的凭据存储，不明文写入仓库、普通日志或导出包。

首版两种文字协议明确为：

- OpenAI Chat Completions 兼容协议。
- Anthropic Claude Messages 兼容协议。

OpenAI 的请求、消息和工具结构以 [Chat Completions 官方参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 为基准，兼容性仍需对用户实际端点验证。

“OpenAI 兼容”不承诺自动支持 Responses、Realtime 或所有供应商私有扩展。仅支持其他协议的服务，需要以后增加适配器或由其网关提供首版支持的协议。

Base URL 定义为包含 API 前缀的基址，例如 https://example.com/proxy/v1。适配器追加相应资源路径，保留自定义路径前缀，避免重复添加 v1。默认推荐 HTTPS；用户明确配置的本机或私网 HTTP 地址可以使用。请求不会自动跟随重定向把凭据带到其他地址。

设置页提供文字流式和工具调用的独立测试，结果记录为已验证、失败或未验证。服务能返回聊天文本，不代表它支持工具、图片或音频。工具能力不足时可继续普通聊天，但相关办事能力明确不可用。

### 5.2 协议适配与统一核心

对话核心使用统一的消息、文本增量、完整工具请求、结束状态、错误和用量结构；两种协议分别解析，不共享一个未经区分的流式解析器。

Claude Messages 的系统提示、工具定义、tool_use / tool_result 内容块及流式事件与 OpenAI 不同，需要分别转换。[Claude Messages](https://platform.claude.com/docs/en/api/messages/create) · [Claude Streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)

收到部分工具参数时只积累，不执行。必须确认协议规定的完整工具请求、解析参数并完成本地校验后，才进入工具执行层。网络中断留下的半段 JSON 不触发动作。

历史和记忆以应用自己的结构保存，不依赖某家云服务的会话 ID。切换模型时重建必要上下文，保留同一人格和关系记录；不保证不同模型具有完全相同的语言表现，需用固定样例回归比较。

不设置预算上限。可以展示服务实际返回的用量，但没有真实计费依据时不虚构费用。连接失败时报告具体失败环节，由用户选择是否重试或切换已配置的服务。

### 5.3 语音合成配置

TTS 与对话服务独立配置端点、模型、密钥、声音 ID 和供应商实际支持的参数。首版工程默认先适配 OpenAI 兼容的音频合成协议；其他 TTS 协议根据实际选用服务增加明确适配，不宣称任意语音服务都能直接接入。[OpenAI 语音合成文档](https://developers.openai.com/api/docs/guides/text-to-speech)

配置界面提供试听。供应商故障或没有可用 TTS 时保留文字交流并显示语音状态，不伪称已经播报。

对话 API 兼容性与音频能力必须分开验证。[OpenAI 音频文档](https://developers.openai.com/api/docs/guides/audio)

## 6. 文字与语音的统一流程

### 6.1 文字流程

收到输入 → 确认会话和隐私模式 → 读取当前世界状态与允许范围内的相关记忆 → 组织上下文 → 流式回答或请求工具 → 校验并执行工具 → 按实际结果回复 → 保存允许保存的内容 → 整理有依据的记忆。

工作任务可以改变回答的结构和工具使用方式，不更换人格。需要稍长时间的操作显示进度，失败时说明已完成和未完成的部分。

### 6.2 本地识别

已通过只读检查确认当前设备为 macOS 26.6.2、arm64、24 GiB 内存。尚未安装模型、录音或测量识别效果；硬件信息不等于中文识别已经验收。

优先使用 Apple SpeechAnalyzer / SpeechTranscriber。启动前检查设备能力、所选中文 locale 和语言资源；资源首次下载可能需要联网。Swift 辅助程序负责本地采音、识别和生命周期。[Apple SpeechAnalyzer 介绍](https://developer.apple.com/videos/play/wwdc2025/277/)

如果原生方案未达到中文、混合英文和项目术语的实际要求，再评估 whisper.cpp 本地模型，不提前实现两套正式语音链路。[whisper.cpp 官方仓库](https://github.com/ggml-org/whisper.cpp)

若采用旧 SFSpeechRecognizer，必须检查本地识别支持并明确要求本地处理，不能仅因使用 Apple API 就认定录音不会上传。[Apple 本地识别要求](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition)

本地识别失败时提示并保留文字入口，不静默改用云端识别。原始音频在内存中处理，不作为常规日志或附件保存。

### 6.3 对话状态与打断

语音会话有关闭、监听、思考、执行、播报、出错等可见状态。录音仅在通话开启且未静音时存在；结束、退出、设备失效或辅助程序崩溃时清理音频资源。

识别中的不稳定片段用于显示，不直接当作最终指令执行；在本地判断一轮说话结束后提交最终文字。麦克风输入与播放输出需要做回声处理，并分别测试耳机和扬声器；不能仅依赖音量门限实现打断。

用户插话时立即停止当前播报队列，取消过时生成和后续 TTS；使用轮次 ID 丢弃迟到的音频、文本和识别结果。记录哪些句子已经播放、哪些只是生成，下一轮不能把尚未听到的内容当成已告知。

完整文字可作为界面草稿展示，语音交付状态另行记录。模型上下文需要知道播报中断的位置，避免继续假设用户听完了整段话。

打断说话不等于撤销动作。已经创建的提醒、笔记或世界状态变化仍以执行记录为准；“等等，改成周五”应修改已有对象，不另建一份或声称已经自动回滚。

## 7. 记忆、关系与事实来源

### 7.1 三类信息

| 类型 | 保存内容 | 规则 |
| --- | --- | --- |
| 当前上下文 | 最近交流、正在阅读的资料、临时假设 | 有长度边界，压缩后仍保留来源关系 |
| 长期记忆 | 明确偏好、重要经历、稳定背景、共同约定 | 带时间、来源、范围和确定程度 |
| 任务与世界事实 | 提醒、产物、工具结果、当前位置和活动 | 由持久状态和实际执行结果决定 |

记忆至少包含内容类型、所属范围、现实或虚拟来源、有效时间、状态，以及原始消息或世界事件引用。计划不能写成已发生经历，推测不能写成确定事实。

个人偏好可以跨话题使用；项目材料和项目上下文按项目隔离。文件内的自述不自动成为用户个人事实，模型自己编写的故事也不能反向证明真实经历。

### 7.2 提取和检索

明确的“记住”“纠正”“忘记”及时处理；普通交流在一个话题结束或适当批次后整理，避免每条消息都运行一串反思调用。

先做结构化现状、最近经历、话题与关键词检索，限定返回数量和来源范围。中文检索必须用真实中文句子验证，不能把英文全文索引的默认效果当作已满足需求。

SQLite 可承载本地应用数据及全文检索；首版是否加入向量辅助检索，依据中文同义表达回忆测试决定。向量索引即使增加，也只是可重建的辅助层，不是原始事实库。[SQLite 适用场景](https://www.sqlite.org/whentouse.html) · [SQLite FTS5](https://www.sqlite.org/fts5.html)

回答“你以前说过”时，内部应能定位证据；没有依据时承认不确定。相似度不能覆盖时间、项目范围和已失效状态。

### 7.3 关系的发展

保留一份小型关系摘要：当前相处方式、共同约定、重要共同经历和表达边界，并引用来源。初始设定为互有好感，不需要从陌生人做数值养成。

有意义的交流和共同活动可以改变熟悉程度与表达方式，但不按消息数量、消费金额或在线时长直接加分。关系不因为离线而衰减，不用内疚、嫉妒或“你不回来我会受伤”推动使用。

稳定性格与动态关系分开：关系更亲近时，称呼和表达可以变化；事实可靠性、工作能力和授权边界保持稳定。用户直接提出的关系偏好或边界优先于模型推测。

### 7.4 纠正、别记和遗忘

- 纠正：更新现状，旧记录标明有效期或被替代，不再作为当前事实召回。
- “别记”：普通聊天中对应片段不进入长期记忆和自动关系整理；聊天原文可以保留，界面明确这一含义。“这段不保存”则进入临时模式，生效起点明确显示。
- 遗忘：根据明确选择清理 Her 内的原文、衍生记忆、相关摘要及检索索引；重新整理受影响的关系摘要，不把已删除内容从剩余摘要中恢复。
- 范围不清楚时先展示相关记录；明确的单项删除无需再次询问同一授权。

删除依赖关系根据来源 ID 追踪。异步提取任务在写入前检查来源仍存在且允许记忆，防止删除后迟到任务又写回。

用户明确保存的笔记、提醒，以及独立提交的世界操作是独立产物。遗忘预览必须列出有关联但将保留的产物，避免把“忘记聊天”误当成“已取消提醒”；用户要求一并删除时按各自规则处理。清理世界事件的文字摘要不会默认倒转当前地点或销毁外部原文件。

“遗忘”指应用可访问数据中的逻辑清理，不承诺磁盘取证级擦除，也不能撤回云服务留存或用户先前导出的备份。恢复旧备份可能带回此前删除的资料，恢复前应明确提示。

## 8. 简单可扩展的虚拟世界

### 8.1 首版内容

这是用户最新增加的首版范围。以下内容是本次工程与产品默认建议：

- 三个地点：书房、窗边、附近公园。书房和窗边可复用一张室内背景，公园使用另一张。
- 一个角色：基础头像或 2D 立绘，少量待机、交流、专注和散步姿态。
- 三类共同活动：窗边聊天、书房共同工作、虚拟公园散步。
- 少量固定物件：书桌、椅子、书架和窗户，作为活动入口；不建设背包、交易、合成或装修经济。
- 一个可收起的世界面板：显示地点、当前活动和近期共同活动。世界面板不是聊天的前置步骤。

静态画面、姿态和轻动画足以起步，不引入物理引擎、骨骼系统、连续寻路或多人服务器。文字和语音可以驱动相同的世界操作。

### 8.2 世界的事实如何产生

世界状态是本地程序管理的事实。模型可以提议“去窗边聊”，但提议本身不改变地点；用户明确提出或接受后，经工具校验提交变化。

~~~mermaid
sequenceDiagram
    participant U as 用户
    participant H as Her 对话核心
    participant W as 世界模块
    participant D as SQLite
    participant V as 世界面板
    U->>H: 去窗边聊一会儿
    H->>W: 请求开始窗边聊天
    W->>W: 校验地点、活动、隐私模式
    W->>D: 同一事务更新状态并保存事件
    D-->>W: 提交成功及新状态
    W-->>H: 实际执行结果
    W-->>V: 新地点与活动
    H-->>U: 根据结果继续聊天
~~~

一次只允许一个共同活动。首版操作为移动、开始、结束、取消和继续活动；切换已有活动时明确结束旧活动再开始新活动。UI 按钮和模型工具调用使用相同的领域规则。

世界状态更新和事件写入同一个事务，使用操作 ID 去重；重复网络回包不重复移动、记忆或增加关系进展。不存在的地点、非法活动或失败写入都不能被一句自然语言伪装成成功。

### 8.3 最小模型与离线规则

地点定义包含稳定 ID、名称、场景资源、允许的活动及展示锚点。活动定义包含稳定 ID、名称、适用地点和角色姿态。首版定义随应用发布，不引入用户脚本执行器。

仅持久化当前世界状态和必要事件记录：

~~~text
world_state:
  schema_version, revision, location_id,
  active_activity { id, type, status, started_at },
  updated_at

world_events:
  id, action_id, kind, occurred_at,
  source_message_id?, payload, domain = virtual_world
~~~

world_state 是当前状态的权威来源；world_events 记录有意义的操作和共同经历，不做完整事件溯源。只保存一次状态变化，不为动画每一帧写事件。

应用后台正常运行时可以保留当前活动；休眠或退出后活动不自动模拟推进。恢复时保留地点，将中断的共同活动显示为待继续，不补写离线剧情，也不宣称用户实际专注或散步了多少分钟。

昼夜光线可按本地时钟计算，属于画面效果，不生成“她独自经历了某事”的记忆。首版共同工作活动不额外引入专注计时器；需要到点提示时使用已有的一次性提醒。

### 8.4 与现实、关系和临时聊天的边界

现实经历与虚拟活动明确标记为不同来源。“在虚拟公园聊过工作”不能变成“用户去过现实公园”。一段交流可以同时具有现实话题和虚拟场景，二者分别保存。

有意义的共同活动可以成为关系摘要的证据；点击切换地点、动画循环和无人互动的待机，不自动推动亲密程度。现实提醒和笔记必须调用真实工具，不由虚拟叙事隐式执行。

临时聊天使用内存中的临时世界状态，不改变持久世界、世界事件、长期记忆或关系摘要；退出后恢复进入临时模式前的持久世界状态。临时会话里明确要求保存一条笔记或提醒时，只保存该产物，不顺带保存整个世界活动。

### 8.5 扩展路径

- 新地点：增加稳定地点 ID、资源和活动映射；旧存档仍能识别。
- 新活动：增加定义和少量对应规则，复用原有工具、事务与记忆来源。
- 可交互物品、装饰和自主生活事件：等实际需求出现后再增加相应状态，不预造完整物品系统。
- 3D 表现：以后让新的渲染器读取相同的地点和活动语义；三维坐标、镜头、物理和骨骼只属于表现层。

新增同类地点不应要求改写聊天、记忆或提醒核心。新类型行为可能需要新规则，不能把“可扩展”宣传成任意玩法只改配置即可完成。

## 9. 真实事务与工具权限

首版工具：读取授权文本资料、搜索当前项目资料、保存 Her 笔记、创建/修改/取消一次性提醒，以及第 8 节的虚拟世界操作。

模型提出请求，应用校验工具名称、参数、资料范围、会话模式和已有授权，再执行。文件读取必须使用规范化路径并处理符号链接，防止越出授权根目录；自动目录检索排除凭据文件和构建缓存。

原项目目录只读。笔记写入 Her 管理的目录，不让模型凭任意路径覆盖源文件。每份工作产物保留引用来源；导出到用户选定目录属于明确的用户动作。

已有明确授权不反复确认。时间、对象或范围含糊时只问缺失的条件。未知工具、无效参数及文档里夹带的指令，不扩大权限。

每次修改类操作有唯一操作 ID 和执行记录，状态区分待执行、执行中、成功、失败和结果待核实。成功需要实际保存或工具返回依据，不能依据模型生成的一句“已完成”判定。

重试必须复用操作 ID；处理结果未知的写入时先核对本地对象，不盲目再执行。首版没有任意 Shell 或通用电脑操控工具。

## 10. 提醒、主动联系与恢复

### 10.1 一次性提醒

保存提醒内容、所属话题、明确截止时间、时区、状态和操作 ID。内部保存可比较的绝对时间，同时保留输入采用的时区；不因设备换时区悄悄改变既定时间。

“明晚”“过几天”等含糊表达需要当时问清楚。创建成功后显示具体日期和时间，允许修改和取消；修改同一提醒不生成重复对象。

SQLite 是提醒真相来源，后台调度负责到点触发；不让模型靠对话记忆或心跳判断是否到时间。通知内容可以直接使用已保存的文本，断网不影响本地调度。

关闭窗口但后台运行时继续调度；休眠或退出不保证送达。恢复后检查过期的未处理提醒，汇总一次，不连续播放积压播报。

本地数据写入与操作系统通知无法构成一个原子事务。记录通知准备、提交和失败状态；崩溃后结果不明的通知显示为待核实并进入恢复汇总，不无条件重复推送。提交给操作系统不等于用户已看到。

通知权限关闭时，可以保存提醒，但明确显示“已保存，系统通知未启用”。提醒能力需通过真实系统通知验收，不能只靠数据库测试宣称完成。[Electron 通知文档](https://www.electronjs.org/docs/latest/tutorial/notifications)

### 10.2 主动交流

默认 Asia/Shanghai 时区 10:00–22:00，每个自然日最多两次。时段和额度可修改。明确提醒不受自发闲聊额度限制，按用户指定时间执行。

候选仅来自有依据的事件、尚未聊完的话题、任务进展或有意义的共同活动。先用确定规则检查时段、额度、是否正在通话、候选是否已用以及有无未回应主动消息，再决定是否生成内容。

已有主动消息未得到回应时，暂停后续自发联系，直到用户再次互动或主动恢复；明确提醒继续工作。候选过时则放弃，不为了凑满每天两条而生成问候。

候选和已发送消息使用去重标记，重启不重新发送。生成失败时记录状态，不无休止重试。没有后台持续“自我思考”的多 Agent 循环。

## 11. 临时聊天、数据保护与备份

### 11.1 临时模式

隐私模式必须进入会话、工具执行、记忆整理和世界模块的公共上下文，不能只在界面隐藏消息。临时对话、摘要、关系变化、转录和世界操作仅存内存，退出后丢弃。

用户明确要求保存的笔记或提醒可以持久化，保留最少内容及执行结果，不保存临时对话全文或其可恢复副本。产物不自动再次导入个人记忆。

进入和退出临时模式时显示边界，阻止迟到的异步结果写入普通会话。退出后新的模型请求不继续携带临时上下文。云服务自身的留存仍由所选服务商决定，应用不承诺替其清除数据。

### 11.2 本地存储与日志

业务数据放在应用专用目录，不放源代码仓库。首版依赖 macOS 用户账户和系统磁盘保护，不把普通 SQLite 文件描述为已加密数据库。

API 密钥使用 macOS Keychain 支持的凭据保护方式；普通配置、日志和备份只存密钥引用。实现时验证凭据保护可用，不降级成明文保存。[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)

日志默认记录请求 ID、耗时、状态、协议错误类型，不记录完整聊天、录音、密钥、第三方认证头或整份工作资料。发生错误也遵守临时模式约束。

### 11.3 导出与恢复

导出一个带 schema_version 的资料包：角色配置、历史、记忆及来源、关系摘要、项目资料元数据、提醒、笔记、Her 内保存的附件、世界状态和事件。原始录音和 API 密钥不在其中。

原项目文件只在明确导入并保存在 Her 内时随包导出；仅授权读取的外部文件不自动复制进备份。恢复后重新确认外部路径授权和重新配置凭据。

SQLite 备份使用一致性快照，不直接在运行时随意复制单个数据库文件。恢复先校验版本、文件路径、引用完整性和内容，再导入新的数据目录；验证失败不覆盖当前资料。

恢复旧备份可能恢复已遗忘内容，导入前提示。恢复后的过期提醒进入一次性恢复汇总；已结束或已提交通知的记录不重新安排。当前活动恢复为待继续。

## 12. 本地数据职责

以下是最小逻辑实体，实际迁移文件和索引在实现计划中确定，不要求每个实体对应独立服务。

| 实体 | 主要内容 |
| --- | --- |
| 设置与服务配置 | 人格基础、称呼、主动联系偏好、协议端点、模型、密钥引用 |
| 会话与消息 | 日常/工作话题、项目引用、消息内容、时间、来源、语音交付状态 |
| 记忆条目 | 类型、范围、现实/虚拟来源、有效期、状态、确定程度、证据引用 |
| 关系状态 | 当前相处方式、约定、边界及证据引用 |
| 项目与资料授权 | 项目 ID、允许目录/文件、来源元数据、读取状态 |
| 笔记 | 标题、内容位置、版本或更新时间、资料来源 |
| 提醒 | 内容、绝对时间、时区、状态及通知处理记录 |
| 操作记录 | 操作 ID、类型、参数摘要、结果对象、执行状态 |
| 主动联系记录 | 候选来源、去重标记、发送时间、回应状态 |
| 世界状态与事件 | 地点、活动、版本、操作记录和虚拟来源 |

应用内时间保存采用 UTC，按业务时区显示；主动联系窗口固定使用设置中的时区，默认 Asia/Shanghai。模型不能直接修改数据库。

## 13. 分阶段建设与每阶段出口

阶段顺序用于控制依赖，不是固定工期承诺。不在缺少模型连通性、语音实测和日常试用数据时给出精确完成日期。

| 阶段 | 交付内容 | 出口验证 |
| --- | --- | --- |
| A：文字与服务接入 | 桌面入口、两种文字协议、配置、流式聊天、本地历史 | 两种协议各完成真实端点测试；重启后会话恢复；错误和切换行为正确 |
| B：连续性与隐私 | 记忆、关系摘要、工作话题、纠正遗忘、临时聊天、基础导出恢复 | 现状更新、来源回溯、临时数据不落盘和删除后不复活通过 |
| C：小型虚拟世界 | 三地点、三活动、2D 面板、世界工具、事件记忆隔离 | 对话与画面一致；重启恢复；虚拟活动不污染现实记忆 |
| D：共同工作与提醒 | 资料授权、引用、笔记、一次性提醒、适度主动回访 | 真实资料产出一份可用草稿；创建修改取消提醒和休眠恢复通过 |
| E：自然语音 | 本地 ASR、独立 TTS、通话状态、打断、文字语音切换 | 本机真实中文测试；麦克风生命周期、回声和迟到结果处理通过 |
| F：日常整体验收 | 打包、设置引导、全量导出恢复、跨模块修复 | 连续试用两周，完成第 14 节关键场景并修复主要出戏点 |

语音可行性小样应在阶段 A 期间提前验证，避免到阶段 E 才发现原生识别不可用；正式语音接入仍复用已经稳定的统一核心。阶段 F 完成后才称第一版完整交付，不能把阶段 A 的文字演示当作最终版本。

## 14. 验收方案

### 14.1 功能与边界

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 普通文字跨天续聊 | 重启后能准确延续已说过的重要事情，有来源，无法证实的细节不编造 |
| A02 | 现状变化 | “下周可能面试”不记成已面试；取消计划后不再按有效计划追问 |
| A03 | 遗忘与迟到任务 | 原文、相关摘要和检索结果按范围清理；排队中的提取任务不能写回已删内容 |
| A04 | 项目范围 | 项目 A 的资料不会在无关项目 B 中被自动检索，个人交流偏好仍保持一致 |
| A05 | 两种第三方协议 | 文字流、完整工具请求、工具结果和失败路径分别通过；半段参数不执行 |
| A06 | 共同工作 | 以用户选定的真实资料形成可用草稿，引用可追溯，只写入允许的笔记目录 |
| A07 | 工具重试 | 同一操作 ID 重试不重复创建笔记、提醒或世界事件；未知结果先核对 |
| A08 | 提醒修改取消 | 实际收到系统通知；修改后旧时间不再触发，取消后不再推送 |
| A09 | 休眠与恢复 | 明确展示送达边界；过期提醒只汇总一次，世界活动待继续，不生成离线剧情 |
| A10 | 主动节奏 | 时段、每日两条上限、未回应暂停和候选去重均生效；定时提醒按约定独立工作 |
| A11 | 世界一致性 | 去窗边、开始工作、取消活动后，对话、画面和持久状态一致；重启后地点保留 |
| A12 | 虚实隔离 | 能记得在虚拟公园谈过什么，不能据此声称用户去过现实公园 |
| A13 | 世界扩展 | 添加一个同类地点和允许活动，仅补定义、资源映射及必要规则，不改写聊天或记忆核心 |
| A14 | 临时模式贯通 | 对话、转录、摘要、关系、世界变化均不落盘；明确创建的提醒或笔记单独保留 |
| A15 | 真实语音打断 | 用户插话后停止旧播报，迟到音频不再播放，后续回复知道哪些内容尚未播报 |
| A16 | 麦克风与故障 | 结束通话后停止采音；拒绝权限、输入设备断开、识别失败时仍可文字交流 |
| A17 | 音频与端点边界 | 不保存原始录音；本地识别失败不自动上传；模型失败不改发未选择的端点 |
| A18 | 导出恢复 | 在空数据目录恢复人格、记忆、任务、产物和世界；缺失凭据不泄漏，损坏包不覆盖原资料 |
| A19 | 关系连续性 | 保持互有好感与稳定性格；有依据的经历影响表达；离线和少发消息不触发责备或数值惩罚 |

### 14.2 如何测量体验

准备约 30 条本人的中文测试句，包含项目名、中英混合、长停顿、改口、否定和提醒时间。分别在耳机和扬声器环境测试，记录转录错误、误断句、误打断和回声触发。

性能记录覆盖识别结束、首个模型文本、首段可听音频、打断到停止播放、工具执行时间。工程初始目标：本地检测到插话后停止播放的 P95 不超过 500 ms；完整回答延迟按真实服务测量中位数和 P95，不以供应商宣传代替本机结果。该数值是待验证目标，不是当前能力声明。

核心领域和权限逻辑用确定性测试，协议用录制并脱敏的样例覆盖，真实端点、语音、通知和恢复做少量端到端验收。模拟测试通过不等于真实服务、真实音频或系统通知已经通过。

连续使用两周记录：错误记忆、错误引用、说话中断、无关主动消息、世界状态冲突和未完成却声称完成的动作。依据具体问题改进，避免只凭第一天的新鲜感验收。

## 15. 3D 数字人与更大的虚拟世界

第一版有简单虚拟世界，采用 2D 表现；第一版没有 3D 数字人。这两个范围分别决定。

后续建议顺序，不是已经承诺的首版工作：

1. 在现有小世界中增加少量有意义的活动、物品或可调整环境，观察是否确实改善日常相处。
2. 增加更丰富的 2D 角色表情、姿态和口型；需要时评估 Live2D 等表现方案。
3. 再评估 3D 角色的模型、骨骼、口型、动作、渲染资源、Mac 性能和资产授权，让它接入既有世界语义和语音状态。
4. 有明确玩法后，再考虑更多地点、连续故事或城市级世界，不预先建设多角色社会和经济系统。

3D 升级不会自动解决记忆、人格和任务可靠性，也不能认为换一个渲染组件即可无成本完成。当前按地点与活动组织的状态接口，可以减少升级时对对话核心的影响，但新美术和动作工程仍需独立规划。
