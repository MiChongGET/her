## 2. 已确定的适配基线

- 继续使用当前 Pi 底座，Pi 会话为聊天历史权威；SQLite 保存 Her 的业务状态，不按旧 v7→v8 迁移读取旧版资料，不恢复旧聊天引擎。
- 产品许可同时满足才可使用，不能用一个全局“可用”取代个人启停、工作共享、独立个人许可、敏感接纳、主动提及限制和接收服务许可。
- 人工查看与模型使用分离；当前、历史、停用、替代记录的可见性，不能由模型选材结果决定。
- 自动整理边界与明确用户指定旧历史补记分离；补记保留真实旧来源，不用复制成新消息绕过基线或撤回。
- 关闭时的新交流起点以及普通请求、压缩、恢复三条路径共同受限制；新服务不能从旧回答或摘要获取未授权内容。
- 遗忘按选定范围真实清理原文及已知派生。实现可行性必须有证据，不能降级为隐藏或仅阻断后仍称已遗忘。
- 保留现有在途工作，不因“未生产接入”假定运行库相关表一定为空，不擅自回滚或清库；实际结构与数据兼容方案留后续只读核对与明确设计。

这些是今天产品决定、当前仓库约束和既有历史权威的衔接，不是对本轮待决范围的预先批准。

## 6. 第一轮：A1–A3 已确认

本轮编号使用 A，避免与已确认的产品 Q1–Q26 及旧 change 的 Q1–Q19 混淆。用户已明确表示“A1、A2、A3 都同意”。以下原推荐记为决定，先确定旧计划中用户可见能力是否保留，不要求用户选择数据库、函数名或分词算法。

### A1：经验流程卡是否独立后置，不纳入本轮记忆适配的必交付范围

旧计划会把成功办事流程提炼为可审核、可复用的经验卡；今天的个人经历、共同经历和关系理解是不同对象，不能互相替代。

决定：本轮完整实现已确认的伙伴记忆与用户控制，经验流程卡另列后续能力，不删除旧需求或实验，也不先做审核队列、卡版本和使用记录。代价是首版暂不提供“从办成的事自动学出办事流程卡”。

状态：2026-10-23 用户明确同意。

### A2：首版是否不新增独立整理模型设置，默认复用所属交流的已获准模型配置

旧计划让用户额外选择整理服务和模型，前台切换不影响它。今天只确认真实接收服务须获准，没有指定必须有独立配置入口。

决定：首版整理使用来源所属交流的模型配置，并且必须满足该接收方对本次材料的实际许可；未获准、配置失效或相关任务已过时时停止并如实显示，不换服务兜底。一次整理绑定其配置与许可，不因前台后续切换而悄悄把材料改发另一个服务；独立设置入口后置。代价是首版不能专门指定更便宜或专用的后台整理模型。

状态：2026-10-23 用户明确同意。这不默认批准空闲调度、每日配额或任何全量历史扫描，也不将“当前模型”当作已经获得全部材料许可。

### A3：独立全历史搜索是否后置，首版聚焦获准记忆召回、来源查看和指定补记

旧计划的 `session_search` 能检索跨会话原始消息；这比“她自然想起已获准记忆”更广，也涉及未共享工作、旧敏感原文和新接收服务的边界。

决定：首版不新增面向模型的跨会话全历史搜索工具或统一全历史搜索产品入口，先完成获准记忆回忆、人工来源查看，以及用户选择旧片段的当次使用或补记。FTS 等检索技术仍可在允许范围内作为实现候选；不改变已存在的普通聊天查看能力。代价是暂时不能让她对全部旧聊天自由搜索来找一段原话。

状态：2026-10-23 用户明确同意。这不删去 Q15/Q24 已确认的明确选择旧材料能力，也不将无搜索入口解释为无须来源校验。

## 7. 第二轮：A4–A5 已确认

用户对本轮 A4、A5 回答“同意”，已确定普通整理何时发生，以及未完成工作在故障、退出和记忆关闭后的体验。候选格式、具体重试次数、队列结构与检索算法由工程提出，不作为本轮用户选择。

### A4：普通记忆是否随已落盘交流逐步整理，前台交流优先

情景：用户说了一个有意义的偏好，紧接着继续聊天。如果必须等五分钟空闲或手动启动才整理，概览可能很久都没变化；如果每次都先等完整整理，聊天会变慢。

决定：普通整理在一轮交流稳定落盘后以小范围触发，使用已获准且尚未处理的新来源；连续输入可合并待处理范围，不要求用户手动开批次，也不照搬旧的五分钟门槛和每日三批产品规则。新的前台交流优先，普通整理可让出执行，不让回答等待额外整理请求。明确的记住、纠正、别记、不主动提及、遗忘与启停走各自操作路径，不排在普通整理之后才使限制生效；只有操作实际完成才反馈成功。普通整理未完成时，当前交流仍可理解用户当次提供的内容，但不假称已经形成长期记忆。

取舍：概览与跨交流可用的记忆可能稍晚于当前聊天；不承诺每句话都立即整理或自动保留。

状态：2026-10-23 用户明确同意。普通整理不能向模型发送超出范围的新旧原文；具体稳定点和调度方式由工程依据当前宿主接点设计。

### A5：未完成整理是否可在退出后恢复，但失败显式重试、关闭时取消旧批次

情景：前台新消息抢占了整理，或 Her 正常退出，用户再次打开时不应以为已记住而实际丢失；另一方面，停用后重开也不能悄悄追赶旧候选。

决定：对记忆仍开启、许可和来源仍有效的待整理新内容，仅持久保存恢复所需的最小来源引用、范围与状态；因前台抢占、休眠或退出未完成时，条件恢复后可以继续，提交前重新核对来源、限制及接收配置。已经失败的整理显示原因并等待明确重试，不无限自动重跑，也不切换服务兜底；失败不影响已经完成的聊天。

恢复仍受 A2 的绑定约束，不能自动改用后来全局选中的服务；原配置已过时或许可不再满足时，先停止并说明，不直接重新派发。

关闭个人记忆时取消其未完成的普通个人记忆整理，重开不自动恢复这批尚未形成记忆的候选，也不回扫关闭期间；用户指定补记另按明确选择处理。既有合法工作整理仍按独立工作范围和共享规则判断，不能因关闭个人记忆取消全部工作。清理或撤权后的迟到结果不能提交，未处理不显示成完成。

取舍：普通前台抢占或退出不会轻易丢掉获准的待处理工作，但失败需要用户重试；主动关闭意味着放弃这批未完成的个人整理。

状态：2026-10-23 用户明确同意。A5 独立于 A4 的具体触发时机，约束任何已存在的普通整理；不把未完成候选视为已经保存的旧记忆，也不替代遗忘清理的恢复规则。

| 现有恢复 | `host.ts:99–145` 将中断任务和队列暂停，避免重复发送；`1095–1135` 的继续建立新请求身份 | 没有自动续跑记忆整理的既有能力；A5 已获准，需独立设计最小恢复状态、幂等与迟到结果防护，不修改前台队列既定恢复语义。 |
| 来源校验 | `host.ts:740–747` 接入的是文件来源校验；`MemoryService` 没有生产装配 | 记忆许可、来源版本、交流起点和接收服务需要真正接入普通请求、压缩和恢复，不以局部 isUsable 检查代替整条路径。 |

下列选择由工程提出具体设计与验证依据，不追加为用户访谈问题：稳定保存后的内部通知、与前台队列的调度接点、工作身份和幂等键、来源水位、配置快照、许可版本、取消传播、读回核对及故障恢复状态。整理不应向用户对话历史写入伪用户消息；也不能为了节省接口改动给来源增加模型自报的许可布尔值。

## 9. 作者提出的最小适配架构

本节是依据 Q1–Q26、A1–A5 作出的工程设计选择，供规划者审阅；不是用户指定了这些接口，也不是实现已完成。选择“保留有效基础、补齐许可与用途、接通真实请求出口”，不整体照搬旧三层记忆和后台批次平台，也不重写整个 AgentHost。

### 9.1 职责和数据流

| 职责 | 消费与产出 | 边界 |
| --- | --- | --- |
| 来源与许可判断 | 真实 Pi entry、记忆/摘要版本、文件依赖、用户明确操作、当前范围与接收服务 → 本次是否允许及理由 | 宿主创建权限依据；模型和 renderer 不能自报已授权。 |
| 记忆业务服务 | 明确操作或合格候选 → 记忆版本、使用限制、来源关系和真实操作状态 | 读取资料、保存个人事实、独立个人许可、敏感分享和服务传输分别检查。 |
| 普通整理 | 稳定且获准的新来源及绑定配置 → 结构化候选或无候选结果 | 单次只读有界材料，无外部工具；前台优先；不写伪用户消息，不复制完整聊天作第二权威。 |
| 请求上下文整合 | 本次范围、交流起点、用户当次触发和接收方 → 合格原交流材料及有限记忆片段 | 普通请求、工具续轮、压缩、恢复都在实际发送前核对，不能仅限制召回入口。 |
| 清理和恢复 | 明确选择的遗忘范围、来源与派生 → 隔离、替代历史验证、清理状态与最终结果 | 与普通整理恢复分离；未清理完不反馈完成，不取消或重放独立外部事务。 |
| 人工控制出口 | 当前/历史/停用状态、来源与范围 → 概览、操作预览和真实反馈 | 人工查看不授予模型许可，不用模型可用列表充当概览。 |

主数据流为：已保存来源 → 校验接纳范围 → 明确操作或普通候选 → 提交前复核 → 业务状态与来源版本；实际回答按本次用途重新选择。模型只能建议内容，不可决定权限、实际业务成功或遗忘完成。

### 9.2 将 C1 的单一 isUsable 拆成按用途判断

不是为每个用途新增服务，而是在统一判断中明确用途和上下文，避免一个布尔值承担互相不同的语义。具体函数签名留实施计划，最低限度的四类出口如下：

| 用途 | 必须提供的上下文 | 不能由其推导的许可 |
| --- | --- | --- |
| 人工概览和来源查看 | 用户选中的条目/历史版本及可见状态 | 模型重新读取、取消不主动提限制或恢复已撤回来源。 |
| 形成/更新记忆 | 真实来源/版本、自动或明确指定范围、记忆开关、敏感意图和绑定处理配置 | 来源在新基线之后不等于允许保存敏感事实，选择一项不等于整库导入。 |
| 用于本次模型请求 | 目标话题、实际接收方、有效许可、交流起点、当次用户触发及容量 | 工作共享不等于个人记忆，记住不等于允许主动提，旧聊天不等于新服务可接收。 |
| 控制性失效或清理 | 用户控制/来源撤回事件、受影响对象及当前操作身份 | 不因此保存新敏感状态、重读停用内容参与回答或取得外部行动权限。 |

独立个人许可保留工作来源，但以真实用户授权及单独可撤回范围通过资格检查；普通工作派生仍依赖当前共享资格。指定补记以选定来源和范围获得例外，不改写来源日期或删除原启用基线。相同正文不合并成更宽权限；支持多个来源时须表达哪些是联合证据、哪些是真正独立支持，不能把缺失的联合证据随意降成单一证明，显式遗忘不借替代证据绕过其选定范围。

### 9.3 最小状态表达

在现有版本、来源依赖和排除基础上，补齐下列信息；可合并到已有存储或使用少量附属记录，不预先建立通用策略引擎。

- 内容与认识：稳定身份、版本、当前/过去适用时间、来源和真实参与程度；推测、未知结果不直接变成现状。
- 许可与使用限制：个人启停及其生效边界、独立个人授权、敏感长期接纳或具体分享意图、不主动提限制、服务接收许可。许可变更须让旧候选和旧暴露资格失效；不用正文关键词猜授权。
- 明确范围：自动启用边界与指定补记范围分开，原工作范围和个人授权分开，人工查看与本次模型使用分开。
- 整理工作：最小来源引用/版本、绑定配置/许可、等待/执行/中断/失败/取消/完成的真实状态及幂等身份，不持久保存额外的全量输入正文。
- 遗忘工作：选择与影响、最小墓碑、阶段、替代映射、保留产物、失败原因与恢复身份，不在清理日志或映射里保留被遗忘正文。

具体列、事务边界和状态枚举由工程结合实际 Store 定义；不能把目前仅有的 active/superseded/excluded 三态当成已表达全部控制。

### 9.4 回忆与整理输入

首版按“当前有帮助且仍获准”从已形成的记忆中选择有界内容，稳定偏好、共同约定可优先，经历和工作进展按当前相关性进入；不是每轮全量注入。没有足够证据时如实不确定，不为了找到答案扩大到全部历史。FTS、普通匹配或其他本地检索方式须用中文相关性、换说法、无答案和同名场景验证，再确定最小实现；不在此承诺词法匹配能完成语义回忆，也不默认增加向量数据库或独立召回模型。

整理输入只使用本次获准的新交流或指定补记材料；原始工作文档/代码/详细讨论不因共享而发送给日常。工作进展依据结构化状态和实际结果，敏感感受按原规则处理。敏感性或授权无法可靠确定时不自动新增相应个人记忆，不把风险原文藏入长期待确认档案。模型候选提交前再次核对来源、授权、目标版本和工作身份；候选过时不覆盖新认识。

## 10. 生命周期、三条请求路径与真实反馈

### 10.1 稳定来源到整理完成

稳定落盘后登记待处理来源，前台有新工作时先让出；开始整理时绑定来源版本、所属配置、实际接收方及许可。恢复只继续符合 A5 的工作，失败待明确重试；来源或配置过时先说明，不自动换服务。提交是一个有证据的内容单元：该单元的有效结果或明确无候选与处理标记一致保存，不能处理完第一个候选就把整条来源标成完成。已经提交的单元不因重试重复写；中断未提交的单元不声称成功。

用户明确记住或纠正走业务操作，不等待普通整理队列。无需模型推断的限制变更先持久生效，阻断相关迟到结果；仍需解析、确认目标或执行清理的操作可以显示处理中，只有相应真实效果完成才反馈成功。当前聊天完成与整理完成是不同结果。

### 10.2 已知来源依赖和发送前过滤

每次模型实际接收的记忆/共享/选定旧片段，保存宿主发出的来源版本和许可边界，并将相关助手输出、工具结果及摘要绑定已知派生依赖。普通用户的新输入保留其自身来源，不能因以前读过某项资料就让所有后来用户输入都成为其派生；但未知身份或缺少边界的旧历史，也不能直接当成新输入放行。

权限、来源或交流起点变化时，使受影响的在途模型工作和未提交候选失效；无依赖工作继续。已送出的内容无法撤回，保证的是不再后续派发、不发布迟到的受限结果。已发生外部动作仍按账本与 unknown 事实处理，不能把记忆变更当作撤销业务或自动重放。

| 路径 | 本次适配必须覆盖 |
| --- | --- |
| 普通请求与工具续轮 | 原用户消息、记忆附加块、旧助手回答、工具参数/返回、系统提示中的任何记忆材料；接收方未获准时，用户选择的新交流只含获准的新输入。 |
| 自动/手动/切模型引发的压缩 | 本次待摘要消息、回合前缀、旧摘要及 context edit/分支摘要；不能用重新压缩把已停用或未获准材料再生成合法来源。 |
| 重启与继续 | 精确会话映射、有效来源与许可、启停起点和跨天边界；旧摘要或恢复投影不能成为绕过限制的入口。 |

过滤无法可靠完成时取消相应发送或压缩并说明原因，不以模型忽略提示代替过滤。能确认其自身仍获准的用户新输入不应因不相关内容失效而一并消失，但不能直接复用当前 guard 对所有未匹配 user 原样保留的兜底。

### 10.3 当前 guard 的具体适配风险

只读核查：`sources.ts:6–21,54–58` 目前只解析文件/授权键，`host.ts:740–745` 仅做文件资格检查，尚无记忆许可和接收方语义。`sources.ts:101,108–110,124` 对未匹配用户消息的空来源放行，`source-guard.ts:13–16` 的异常兜底也原样保留 user，且只覆盖其他角色的 content，不能据此证明独立 summary 字段被清理；正常占位逻辑 `sources.ts:87` 才专门处理 summary。未来适配须逐类检验所有出口，包括 system prompt，不是只给现有 valid 回调补一个总开关。本轮未运行探针，不将这些接点风险描述成已经发生的泄露。

## 11. 存储兼容与完整遗忘的工程门槛

### 11.1 当前 v1 的兼容方式

保留 Her-Pi-v1 与当前历史权威；在后续实施前只读核对实际结构及必要的存在/计数信息，不能因 C1 没接入而假定无数据。新增状态按最小、可审阅的 v1 兼容方案处理，不扫描旧版库。已存在但缺少新许可证明的条目不自动获得模型资格；保留可解释状态和人工控制，必要时由用户重新明确选择，不静默补授同意或导入全部旧消息。

本轮不改 schema、开用户库、清空或回滚任何数据。具体升级步骤、失败恢复及对已有在途结构的处理须写入后续工程任务，不能只改 TypeScript 后假定现有库同步具备新字段。

### 11.2 公开 SDK 重建仍是待证可行性

锁定 SDK 1.3.0 的公开 `session-manager.d.ts` 有 create/open、append、branch、context edit 等声明，但同时声明历史 append-only；省略模型上下文不等于删除原文，单路径提取不等于保留完整分支树。现有文件清单未发现旧 C 计划要求的 forget-rebuild 测试/报告或 history-cleanup 实现；已有持久化探针不证明遗忘可行。

后续进入明确授权的实施后，须先用隔离合成数据验证公开 API 能同时满足：

1. 清理目标原文及已知派生，覆盖所有分支、压缩、context edit、分支摘要、工具调用/结果、标签及 Her 自定义记录中的正文和引用。
2. 保留非目标内容的父子树、活动叶、工具配对、模型/会话信息、原展示时间和来源关系；映射新 ID 不使已撤回、排除、基线前或已停用内容重新获准。
3. 新会话能公开重开、解析、投影并继续，全部删除也能形成有效空会话；未知类型或不能保留的内容明确阻塞，不静默丢弃。
4. 不用私有 rewrite/persist、不手改 JSONL、不留下未披露旧文件副本。公开 API 不能满足时，将完整遗忘及依赖它的完整交付标为未完成，不降级为仅隐藏。

这是工程可行性门槛，不让用户选择 SDK 函数。本轮不编写或运行探针，不承诺这些条件已经被证明。

### 11.3 清理恢复与反馈

建议流程为：冻结相关派发及提交 → 持久化最小清理身份与墓碑 → 构建并核验替代历史 → 事务切换精确会话和来源映射 → 清理旧文件、受影响正文副本/请求队列/草稿/缓存/索引 → 重建展示投影 → 核对完成效果。每步必须可恢复且幂等，新的历史映射不能靠“目录第一个文件”决定。

清理只覆盖用户选定及明确派生的范围，独立成果和外部文件按预览说明，不能随手扩大删除。保留动作账本必要身份、执行或 unknown 状态，清理依赖来源的正文载荷，不重放或取消独立委托。处理中、删除失败或未知类型分别如实显示；在不能确认新请求不含受限材料时，相关请求保持隔离，无关联交流和工作不作全局封锁。逻辑清理不承诺服务方撤回、外部导出删除或磁盘取证级擦除。
