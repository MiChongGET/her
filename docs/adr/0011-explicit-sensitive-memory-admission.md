# 敏感聊天不自动形成长期个人记忆

私人伙伴需要理解用户的处境，但开启个人记忆不应让每次敏感倾诉自动变成长久记录。用户于 2026-10-23 确认：健康状况、亲密关系、财务困境等敏感内容，默认仅用于当前交流，明确交代记住时才纳入相应长期记忆范围；不重复要求点击确认，口令、验证码和完整支付凭据不作为伙伴记忆。这会减少自动沉淀的敏感内容，换取用户更清楚的记忆意图；聊天原文的保留或清理另按记录、临时交流与遗忘规则处理，用户随后确认 Q9：允许长期记住也不等于允许随时主动提起，仅在与当前话题或明确需求直接相关时适度使用；当次表示不想谈就停止追问，不擅自将其解释为删除或遗忘。用户又确认 Q13：可保留记忆但持续限制主动提起，用户一次主动询问仅允许当次交流使用，不自动解除之后的限制。Q19 又明确：普通工作进展共享不自动包含敏感倾诉，敏感分享须明确内容与范围，且分享不等于长期个人记忆许可。Q22 已确认：明确变化使旧敏感状态停止作为当前事实，只保留必要失效状态，不自动新增新敏感记忆；用户明确交代后再长期保存新状态。

Q26 明确将必要失效处理限定为停用期间的最小例外，详见 [ADR-0013](0013-memory-off-stops-use-without-erasure.md)；这项例外不授权新增敏感事实或使用旧敏感内容参与回答。
